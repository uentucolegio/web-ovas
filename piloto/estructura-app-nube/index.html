Avanza con las flechas → ↓ o deslizando la pantalla

🖥️ Detrás de un clic

Cuando usas una aplicación web ves una pantalla, haces clic y los datos aparecen casi al instante. Pero esa experiencia depende de varias piezas que, en la nube, pueden vivir en servicios y zonas distintas:

🎨Frontend

La pantalla que ves: HTML, CSS y JavaScript en tu navegador.

🧠Backend / API

Recibe tu petición, aplica las reglas y empaqueta la respuesta.

🗄️Base de datos

Guarda y busca la información de forma persistente.

🌐Red

Conecta todo: internet, balanceadores y redes privadas.

✨ Al terminar vas a poder leer un diagrama de arquitectura en la nube y entender qué hace cada pieza, y por qué tu app responde rápido… o lento.

🎯 Objetivos de aprendizaje

  • 🧠
    Describir las arquitecturas básicas de aplicaciones web en la nube, identificando los componentes que conforman una solución típica (frontend, backend, base de datos y red) e interpretando diagramas de arquitectura cloud.
  • 🛠️
    Reconocer las herramientas con las que los desarrolladores interactúan con los proveedores de nube (consola web, CLI y SDK), como punto de partida para trabajar con estas plataformas.

🛰️ La vida de una petición

Un diagrama es una foto fija; una aplicación es movimiento. Haz clic en «Ver mi perfil» y sigue la petición.

  1. 👤
    UsuarioEl navegador envía GET /perfil: sale por el router hacia internet.
  2. ⚖️
    BalanceadorRecibe la petición y la reparte al servidor menos ocupado.
  3. 🧠
    Backend / APIValida la sesión y decide qué datos necesita.
  4. 🗄️
    Base de datosBusca el perfil y lo devuelve al servidor.
  5. ✅
    RespuestaEl servidor arma el JSON y tu navegador pinta el perfil.

📈 Escalar sin morir: vertical vs horizontal

Tu app funciona con 10 usuarios. ¿Y si mañana llegan 10.000 de golpe porque se hizo viral? 🚀 Hay dos formas de crecer:

⬆️ Escalado vertical

Hacer más grande el mismo servidor (más CPU, más RAM). Simple, pero tiene un techo físico y un solo punto de fallo.

➡️ Escalado horizontal

Añadir más servidores y repartir el tráfico con un balanceador de carga. Es como abrir más cajas en un supermercado. 🛒

📐 Actividad 2 · Diagrama de una app conocida

                
Elige una app web que uses (red social, streaming, tienda) y propón su arquitectura en la nube: frontend (¿dónde viven los archivos estáticos?), backend/API, base de datos (¿relacional o NoSQL? ¿gestionada?) y al menos un componente adicional (CDN, balanceador, caché o cola de mensajes). 🧰 Actividad 3 · Consola, CLI y SDK

Luego responde: si desplegaras tu proyecto en cada cambio, ¿cuál usarías y por qué? Producto: tabla y respuesta justificada.
