🧠 Resolución de problemas con ciclos

Comprender la sintaxis de un bucle es solo el primer paso; el verdadero reto para quien aprende a programar es reconocer qué tipo de problema tiene delante y qué patrón de repetición le corresponde. La mayoría de los problemas que un programador resuelve en su día a día —sumar valores, contar elementos que cumplen una condición, buscar un dato específico o validar que el usuario ingrese información correcta— no son distintos entre sí en su estructura profunda: todos se apoyan en un pequeño conjunto de patrones que, una vez interiorizados, permiten resolver una enorme variedad de situaciones con seguridad y rapidez.

En el contexto de pequeños negocios y entidades de Montería y la región del Sinú, estos patrones aparecen constantemente: una tienda que necesita calcular el total y el promedio de ventas del día, una cooperativa agrícola que cuenta cuántos productores entregaron más de determinada cantidad de cosecha, o un sistema escolar que busca el registro de un estudiante específico dentro de una lista.

✨ Dominar estos patrones de resolución de problemas con ciclos es una competencia directamente aplicable a las necesidades reales del entorno productivo local. 🌱

🎯 Objetivos de aprendizaje

  • 🧩 Aplicar estructuras iterativas en la resolución de problemas que requieren repetición controlada.
  • 🔍 Identificar y utilizar los patrones más frecuentes de acumulación, conteo y búsqueda de datos.
  • 🎯 Seleccionar la estructura de control (Para, Mientras o Repetir Mientras Que) más adecuada según el problema.
  • 📊 Aplicar bucles anidados y validación de datos en la resolución de problemas bidimensionales.

El patrón de acumulación se emplea cuando es necesario combinar sucesivamente varios valores en un único resultado, típicamente mediante una suma. Requiere una variable acumuladora que se inicializa en el elemento neutro de la operación —cero para la suma— y que se actualiza en cada iteración del bucle sumándole el nuevo valor leído. Calcular un promedio es una extensión directa de este patrón: se acumula la suma de los valores y, de forma independiente, se cuenta cuántos valores se procesaron, dividiendo al final la suma entre el conteo.

➕ Una tienda de insumos agrícolas de Montería que registra sus ventas diarias en una lista puede usar este patrón para calcular el total vendido y el promedio por venta.

El patrón de conteo condicional se utiliza cuando se necesita saber cuántos elementos de un conjunto cumplen una determinada condición, sin importar sus valores exactos. A diferencia del acumulador, aquí la variable contador solo se incrementa en uno cuando la condición evaluada resulta verdadera; el resto de las iteraciones no modifican su valor. Este patrón responde a preguntas del tipo '¿cuántos productos superan cierto precio?' o '¿cuántos estudiantes aprobaron la evaluación?'.

🔢 Una biblioteca municipal de Montería puede usar este patrón para saber cuántos libros de una lista pertenecen a la categoría 'Ciencia Ficción'.

El patrón de búsqueda lineal recorre los elementos de una lista, uno por uno, comparando cada elemento con el valor buscado, hasta encontrar una coincidencia o hasta agotar todos los elementos disponibles. Requiere dos variables de control: un índice que avanza en cada iteración y un indicador booleano que señala si el elemento ya fue encontrado, de modo que el bucle pueda detenerse tan pronto como se produzca la coincidencia, sin recorrer elementos innecesarios.

🔎 Detener el bucle en cuanto se encuentra el elemento buscado evita recorrer innecesariamente el resto de la lista, lo que hace la búsqueda más eficiente que un recorrido simple sin condición de parada.

Reconocer el patrón del problema es solo la mitad del análisis: también es necesario decidir qué estructura de control (Para, Mientras o Repetir Mientras Que) es la más adecuada para implementarlo. Esta decisión depende principalmente de si el número de repeticiones se conoce con anticipación o si, por el contrario, depende de una condición que solo puede evaluarse durante la ejecución del algoritmo.

⚙️ En la práctica, muchos algoritmos combinan ambas lógicas: por ejemplo, un bucle Para puede recorrer una lista de tamaño conocido mientras que, dentro de él, un bucle Mientras controla la validación de cada dato individual antes de procesarlo.

Cuando el problema involucra una estructura de dos dimensiones, como una matriz, una tabla o un tablero, es necesario anidar dos bucles: el bucle externo recorre una dimensión (por ejemplo, las filas) y, por cada iteración del bucle externo, el bucle interno recorre completamente la otra dimensión (las columnas). Es fundamental utilizar variables de control distintas para cada bucle, de modo que no interfieran entre sí.

Bucles de validación de entrada

Un uso particularmente frecuente del bucle Repetir Mientras Que es la validación de datos ingresados por el usuario: el bloque de instrucciones solicita el dato y se repite hasta que el valor ingresado cumpla con el criterio esperado.

🧩 La habilidad para combinar correctamente bucles anidados y validación de datos es lo que distingue a un algoritmo robusto de uno frágil ante datos inesperados.

✍️ Actividades

🌾 Actividad 1: Trazabilidad de patrones (Individual)

Una tienda de insumos agrícolas de Montería registra las ventas diarias en una lista de valores. Diseña en PSeInt un algoritmo que, usando el patrón de acumulación, calcule el total vendido y el promedio por venta, y que además, usando el patrón de contador condicional, indique cuántas ventas superaron los $100.000. Documenta en comentarios cuál variable cumple el rol de acumulador y cuál el de contador.

📝 Producto esperado: pseudocódigo del algoritmo con ambos patrones aplicados y comentarios identificando cada variable.

🔎 Enfoque: distinguir con claridad el rol del acumulador frente al del contador condicional.

👥 Actividad 2: Búsqueda y validación en equipo (Grupal)

En equipos de 3 estudiantes, desarrollen un algoritmo que reciba una lista de códigos de productos y busque, mediante búsqueda lineal, si un código ingresado por el usuario existe en la lista. El código a buscar debe solicitarse mediante un bucle de validación que obligue a ingresar solo códigos de 4 dígitos numéricos. Presenten la traza de ejecución para un caso donde el código exista y otro donde no exista.

📝 Producto esperado: pseudocódigo del algoritmo y traza de ejecución para ambos casos (código encontrado y no encontrado).

👥 Modalidad: trabajo colaborativo en equipos de tres estudiantes.

Cuestionario de autoevaluación sobre los patrones de acumulación, conteo condicional y búsqueda lineal, la selección de estructuras de control y los bucles anidados.
