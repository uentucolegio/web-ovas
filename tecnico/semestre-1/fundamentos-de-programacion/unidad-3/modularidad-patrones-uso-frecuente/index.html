🧩 Modularidad y Patrones de Uso Frecuente

A medida que un algoritmo crece, resolverlo todo en un único bloque de instrucciones se vuelve difícil de leer, de probar y de corregir. La modularidad propone dividir un problema grande en partes más pequeñas y manejables, llamadas subprocesos, cada una encargada de una tarea específica.

Es la misma lógica que usa un restaurante: en lugar de que una sola persona cocine, sirva y cobre, el trabajo se divide en cocina, meseros y caja. Cada subproceso 'sabe' hacer una cosa bien, y el proceso principal simplemente los llama cuando los necesita.

✨ Además de aprender a modularizar, en este tema se estudian patrones de uso frecuente —como la búsqueda del máximo o el menú de opciones— que aparecen una y otra vez al resolver problemas de programación. 🔁

🎯 Objetivos de aprendizaje

  • 🧠 Comprender el concepto de modularidad y sus beneficios frente a un algoritmo monolítico.
  • 🔧 Reconocer la sintaxis para definir e invocar un subproceso, incluyendo el paso de parámetros y el valor de retorno.
  • 🔁 Identificar y aplicar patrones de uso frecuente, como el patrón máximo-mínimo y el patrón de menú de opciones.
  • 🧩 Aplicar la modularidad para descomponer un problema en subprocesos independientes.

La descomposición modular consiste en dividir un problema grande en módulos más pequeños, cada uno responsable de una parte específica de la solución. Esto facilita el trabajo en equipo, la reutilización de código y la detección de errores, ya que cada módulo puede probarse por separado.

Ventaja: claridad

Cada módulo tiene un propósito único y fácil de entender.

Ventaja: reutilización

Un subproceso bien diseñado puede usarse en varias partes del sistema, o incluso en otros proyectos.

Ventaja: mantenimiento

Corregir un error dentro de un módulo no afecta el funcionamiento de los demás.

Un subproceso (también llamado función o procedimiento en otros lenguajes) se define una sola vez y se puede invocar (llamar) tantas veces como sea necesario. Al definirlo se especifican sus parámetros de entrada y, opcionalmente, un valor de retorno; al invocarlo, se le envían valores concretos para esos parámetros.

Sintaxis de definición

SubProceso variable_retorno <- NombreSubProceso(parámetros)
  // Instrucciones
FinSubProceso

Sintaxis de invocación

resultado <- NombreSubProceso(valores_reales)

🔗 Los nombres de los parámetros dentro del subproceso (n1, n2, n3) no tienen que coincidir con los nombres de las variables que se envían al invocarlo (nota1, nota2, nota3): lo que importa es el orden y la cantidad.

El patrón máximo-mínimo es una secuencia de pasos que se repite constantemente al buscar el valor mayor (o menor) dentro de un conjunto de datos: se toma el primer valor como referencia inicial, y luego se compara cada uno de los valores restantes contra esa referencia, actualizándola cuando se encuentra uno mayor.

Variante mínimo

El mismo patrón funciona para encontrar el valor menor, cambiando la condición 'valor > max' por 'valor < min'.

El patrón de menú de opciones se usa cuando un programa debe ofrecer varias acciones al usuario y repetir la presentación del menú hasta que este decida salir. Combina un ciclo Repetir con una estructura de selección múltiple (Según la opción).

Estructura clave

Repetir → Mostrar menú → Leer opción → Según la opción → Ejecutar acción → Hasta Que opción = Salir.

Combinando modularidad y el patrón de menú, cada acción del menú se puede delegar a un subproceso independiente. Así, el proceso principal solo se encarga de mostrar el menú y decidir a qué subproceso llamar, mientras cada subproceso resuelve su propia tarea.

🎯 Modularizar un menú de esta forma facilita agregar nuevas opciones en el futuro: basta con crear un nuevo subproceso y añadir una opción más al Según la opción, sin tocar el resto del sistema.

✍️ Actividades

☕ Actividad 1: Subproceso reutilizable (Individual)

Diseña un subproceso llamado EsPrimo que reciba un número entero y retorne un valor lógico indicando si es primo o no, y luego invócalo desde un Proceso Principal que lea varios números y muestre cuáles son primos.

📝 Producto esperado: el pseudocódigo completo, con la definición del subproceso claramente separada de su invocación.

🔎 Enfoque: aplicar correctamente la sintaxis de definición, parámetros y valor de retorno de un subproceso.

👥 Actividad 2: Menú modularizado (Grupal)

En grupos de máximo tres integrantes, diseñen un algoritmo con un menú de opciones (por ejemplo, para gestionar una lista de tareas) en el que cada opción del menú se resuelva mediante un subproceso independiente.

📝 Producto esperado: el pseudocódigo del Proceso Principal junto con los subprocesos correspondientes a cada opción del menú, y un diagrama que muestre cómo se relacionan entre sí.

👥 Modalidad: trabajo colaborativo en equipos de máximo tres estudiantes.

✔️ Evaluación

Cuestionario de autoevaluación sobre descomposición modular, sintaxis de subprocesos, el patrón máximo-mínimo y el patrón de menú de opciones.
