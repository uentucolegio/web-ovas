🔍 Pruebas de Escritorio y Verificación de Algoritmos

Antes de confiar en que un algoritmo funciona, es necesario verificarlo. Una de las técnicas más útiles para hacerlo sin necesidad de un computador es la prueba de escritorio: ejecutar el algoritmo a mano, línea por línea, registrando el valor de cada variable en una tabla.

Así como un chef prueba una receta paso a paso antes de servirla, un programador debe 'probar' su algoritmo con datos concretos antes de darlo por terminado. Esto permite detectar errores lógicos que no siempre son evidentes con solo leer el pseudocódigo.

✨ Dominar la prueba de escritorio, el análisis de valores límite y la partición de equivalencia permite detectar errores antes de escribir una sola línea de código real. 🧪

🎯 Objetivos de aprendizaje

  • 🧠 Comprender el propósito de una prueba de escritorio como técnica de verificación manual de algoritmos.
  • 📋 Construir tablas de traza que registren la evolución de las variables durante la ejecución de un algoritmo.
  • 🎯 Aplicar el análisis de valores límite para diseñar casos de prueba representativos.
  • 🧩 Diferenciar el análisis de valores límite de la partición de equivalencia como técnicas complementarias.

Una tabla de traza es una herramienta que permite seguir, paso a paso, cómo cambian los valores de las variables de un algoritmo a medida que se ejecutan sus instrucciones. Cada fila de la tabla representa un momento de la ejecución (una iteración o una instrucción), y cada columna representa una variable.

Columnas típicas

Iteración, cada variable relevante del algoritmo, y un comentario que explica el cambio.

Utilidad

Permite ver de forma ordenada el valor final que tomará cada variable, sin necesidad de ejecutar el algoritmo en un computador.

La prueba de escritorio sigue un procedimiento ordenado: se elige un caso de prueba, se construye la tabla de traza, se ejecuta el algoritmo manualmente registrando cada cambio de variable, y finalmente se compara el resultado obtenido con el resultado esperado.

Si coincide

El algoritmo se considera correcto para ese caso de prueba en particular.

Si no coincide

Es necesario revisar el algoritmo: puede haber un error en una condición, una asignación o el orden de las instrucciones.

🔁 Un algoritmo correcto para un caso de prueba no significa que sea correcto para todos: por eso es importante elegir varios casos representativos.

El análisis de valores límite es una técnica para elegir casos de prueba que se ubican justo en los bordes de los rangos válidos e inválidos de una entrada: el valor justo antes del límite, el valor límite mismo, y el valor justo después. Es en esos bordes donde suelen aparecer los errores de programación.

Valores 'Error'

Están fuera del rango válido: deben ser rechazados por el algoritmo.

Valores 'Borde'

Son los límites exactos del rango válido: deben ser aceptados.

Valores 'Normal'

Están claramente dentro del rango válido, sin cercanía a los límites.

Al aplicar el análisis de valores límite sobre un algoritmo real de validación, se construye una tabla completa con todos los casos de prueba elegidos, el resultado que se espera obtener y el resultado que realmente arroja el algoritmo al ejecutarlo con esos valores.

✅ Cuando el resultado esperado coincide con el resultado obtenido en todos los casos, se gana confianza en que la condición del algoritmo está correctamente escrita.

El análisis de valores límite no es la única técnica de diseño de casos de prueba. La partición de equivalencia consiste en agrupar las entradas posibles en clases donde se espera el mismo comportamiento, y probar solo un valor representativo de cada clase, en lugar de probar los bordes.

Se complementan

Usar ambas técnicas juntas ofrece una cobertura de pruebas mucho más completa que usar solo una de ellas.

✍️ Actividades

☕ Actividad 1: Tabla de traza de un algoritmo con ciclo (Individual)

Diseña un algoritmo sencillo que calcule el producto de los primeros cinco números naturales usando un ciclo Para, y construye su tabla de traza completa, mostrando cómo cambia cada variable en cada iteración.

📝 Producto esperado: el pseudocódigo del algoritmo junto con su tabla de traza completamente diligenciada.

🔎 Enfoque: registrar con precisión el valor de cada variable después de cada instrucción del ciclo.

👥 Actividad 2: Diseño de casos de prueba (Grupal)

En grupos de máximo tres integrantes, elijan un algoritmo de validación de datos (por ejemplo, validar que una nota esté entre 0 y 5) y diseñen casos de prueba aplicando tanto el análisis de valores límite como la partición de equivalencia.

📝 Producto esperado: una tabla comparativa con los casos de prueba de ambas técnicas y el resultado esperado para cada uno.

👥 Modalidad: trabajo colaborativo en equipos de máximo tres estudiantes.
