¡Más allá de CRUD! 🚀

Cuando empezamos a programar, las operaciones CRUD (Crear, Leer, Actualizar y Eliminar) son como nuestro primer set de herramientas básicas. Funcionan perfecto cuando estamos aprendiendo, pero imagina que intentas construir una casa entera usando solo un martillo... ¡no sería suficiente! 🏠🔨

En el mundo real, las aplicaciones necesitan hacer cosas más sofisticadas: buscar productos específicos en una tienda con miles de artículos, mostrar solo los 10 resultados más relevantes, o asegurar que cuando alguien compra un producto, el inventario se actualice y el pedido se registre correctamente. ¡Todo al mismo tiempo! 🛒💳

Aquí es donde entran las técnicas avanzadas de acceso a datos. No se trata solo de guardar y recuperar información, sino de hacerlo de forma inteligente, eficiente y segura. Vamos a aprender cómo conectar datos entre sí, filtrar información como un experto, manejar grandes volúmenes de datos sin que tu aplicación se congele, y proteger la integridad de la información cuando varias cosas suceden a la vez.

✨ Al finalizar, serás capaz de construir APIs que manejan datos como un profesional, listas para escalar y enfrentar cualquier desafío del mundo real. ¡Vamos a convertirte en un maestro del acceso a datos! 🚀 🎯

Imagina que entras a una biblioteca con millones de libros y quieres encontrar algo específico. ¿Recorrerías todos los libros uno por uno? ¡Por supuesto que no! Usarías el catálogo para filtrar por autor, género o año. En bases de datos es lo mismo 📚.

Los filtros son como el buscador de Netflix. No ves todas las películas existentes, solo las que coinciden con tus criterios: "comedia", "2023", "menos de 2 horas". ¡Eso es un filtro en acción! 🎬

En una API REST, los filtros se implementan mediante parámetros en la URL:

En el mundo real, los datos no viven aislados. Un cliente tiene pedidos, cada pedido tiene productos, y cada producto pertenece a una categoría. Estas conexiones son las relaciones 🔗.

💡 Analogía:

Piensa en las redes sociales. Tú (usuario) tienes amigos (relación), publicas fotos (relación), y cada foto tiene likes (relación). ¡Todo está conectado! 📱👥

Los tipos de relaciones más comunes son:

1️⃣ Uno a Uno (1:1)

Cada registro de una tabla se relaciona con máximo un registro de otra tabla. Ejemplo: Una persona y su documento de identidad.

2️⃣ Uno a Muchos (1:N)

Un registro de una tabla se relaciona con muchos registros de otra. Ejemplo: Un cliente tiene muchos pedidos.

3️⃣ Muchos a Muchos (N:M)

Muchos registros de una tabla se relacionan con muchos de otra. Ejemplo: Estudiantes y cursos (un estudiante toma muchos cursos, un curso tiene muchos estudiantes).

¿Alguna vez has buscado algo en Google y visto "página 1 de 10" al final? ¡Eso es paginación! 📄 En lugar de enviar 10,000 resultados de golpe, envías 20 o 50 a la vez. Es más rápido y consume menos recursos.

⚠️ ¿Por qué es importante?

Sin paginación, tu API podría enviar megabytes de datos en una sola respuesta. El navegador se congelaría, el servidor se saturaría, y el usuario se iría frustrado. ¡La paginación salva el día! 🦸‍♂️

Los parámetros de paginación más usados son:

GET /productos?page=1&limit=20

Donde:

  • page: número de página (empezando desde 1)
  • limit: cantidad de registros por página

Para calcular el offset (desplazamiento):

offset = (page - 1) * limit

Imagina que transfieres dinero de tu cuenta a la de un amigo. ¿Qué pasaría si el sistema debita tu cuenta pero, por un error, nunca acredita la cuenta de tu amigo? ¡Tu dinero desaparecería! 😱 Las transacciones evitan esto.

💡 Analogía:

Una transacción es como un paquete "todo o nada". O todas las operaciones se completan con éxito, o ninguna se aplica. Es como comprar en línea: o pagas y recibes el producto, o no pasa nada y te devuelven el dinero. 💳📦

🔍 Actividad 1: Diseño de filtros

Diseña un sistema de filtros para una API de productos de una tienda virtual. Debe permitir filtrar por: categoría, rango de precios (mínimo y máximo), disponibilidad y calificación mínima. Documenta los endpoints con sus parámetros y ejemplos de uso.

🔗 Actividad 2: Modelado de relaciones

Crea un diagrama entidad-relación para un sistema de gestión de una biblioteca. Debe incluir al menos las entidades: Libros, Autores, Categorías, Usuarios y Préstamos. Identifica y documenta todas las relaciones entre estas entidades (1:1, 1:N, N:M).

📝 Producto esperado: Diagrama ER con al menos 5 entidades y 4 relaciones documentadas.

🔒 Actividad 3: Implementación de transacción

Implementa una transacción simple en tu API para el proceso de compra: (1) verificar stock del producto, (2) descontar del inventario, (3) crear el pedido, (4) registrar el pago. Si alguna operación falla, ninguna debe aplicarse. Usa el patrón de arquitectura por capas.

📝 Producto esperado: Código funcional de la transacción con manejo de errores.
