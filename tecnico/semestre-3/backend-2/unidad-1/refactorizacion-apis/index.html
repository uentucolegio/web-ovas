Refactorización de APIs: Organiza tu código como un profesional 🔧

Imagina que tienes una habitación donde tiras toda la ropa: camisas, pantalones, calcetines, todo en un montón gigante. Funciona, pero cuando necesitas algo específico... ¡es un caos! 😅 Lo mismo pasa con el código de una API cuando crece sin organización.

Las aplicaciones web modernas (como las que usas todos los días: Netflix, Instagram, Spotify) tienen un backend que procesa millones de peticiones. Si todo el código está mezclado en un solo archivo, se vuelve imposible de mantener, escalar y trabajar en equipo.

La arquitectura por capas es como organizar esa habitación: camisas en un lado, pantalones en otro, calcetines en cajitas. Cada capa tiene una responsabilidad específica y se comunica solo con las que necesita. Esto hace tu código más limpio, reutilizable y fácil de entender. 🏗️

✨ En este OVA aprenderás a transformar una API desorganizada en una estructura profesional usando rutas, controladores, servicios y repositorios. ¡Tu código futuro te lo agradecerá! 🚀

Objetivos de aprendizaje

  • 🧠 Analizar las limitaciones de una API desarrollada sin una arquitectura claramente definida, identificando problemas relacionados con el mantenimiento, la reutilización del código y la escalabilidad.
  • 💡 Comprender la función y responsabilidad de cada una de las capas que conforman una arquitectura Backend moderna: rutas, controladores, servicios y repositorios.
  • 🔧 Aplicar el proceso de refactorización de una API REST existente mediante la separación adecuada de responsabilidades, favoreciendo la organización del proyecto y la reutilización del código.

Cuando empiezas a programar, es natural poner todo en un solo archivo: rutas, consultas a la base de datos, validaciones... todo junto. Funciona al principio, pero cuando el proyecto crece, se convierte en un dolor de cabeza. 🤯

Refactorizar significa reorganizar el código para mejorar su estructura sin cambiar lo que hace el sistema. Es como reorganizar tu habitación: sigue teniendo las mismas cosas, pero ahora están en orden y son fáciles de encontrar.

La arquitectura por capas divide tu aplicación en componentes independientes, donde cada uno cumple una función específica. Es como una empresa: cada departamento hace su trabajo y se comunica solo con los que necesita.

En una API REST con Express.js, las capas principales son:

🛣️ Rutas (Routes)

Definen los endpoints de la API. Reciben las peticiones HTTP y las envían al controlador.

🎮 Controladores (Controllers)

Validan los datos y coordinan la lógica. Llaman a los servicios y devuelven la respuesta.

⚙️ Servicios (Services)

Contienen la lógica de negocio. Procesan datos y aplican reglas del sistema.

💾 Repositorios (Repositories)

Manejan el acceso a datos. Se comunican con la base de datos y devuelven entidades.

Los middlewares son funciones que se ejecutan antes de que la petición llegue a tu controlador. Son como los guardias de seguridad de un edificio: verifican quién entra, si tiene permiso, y solo dejan pasar a los autorizados. 🛡️

Usos comunes de middlewares:

  • Autenticación: Verificar si el usuario está logueado
  • Validación: Comprobar que los datos son correctos
  • Logging: Registrar cada petición para debugging
  • CORS: Controlar quién puede acceder a tu API

Veamos un ejemplo concreto de cómo refactorizar un endpoint de una API. Imaginemos que tenemos una ruta para crear usuarios que actualmente tiene toda la lógica mezclada.

❌ ANES (Todo en un solo archivo)

// app.js - Todo mezclado
app.post('/users', async (req, res) => {
  // Validación
  if (!req.body.name || !req.body.email) {
    return res.status(400).json({ error: 'Faltan datos' });
  }
  
  // Consulta a base de datos
  const user = await db.query(
    'INSERT INTO users (name, email) VALUES (?, ?)',
    [req.body.name, req.body.email]
  );
  
  // Lógica de negocio
  const welcomeEmail = sendWelcomeEmail(req.body.email);
  
  // Respuesta
  res.status(201).json({ id: user.id, name: req.body.name });
});

✅ DESPUÉS (Arquitectura por capas)

// routes/users.js
router.post('/users', userController.create);

// controllers/userController.js
async create(req, res) {
  const data = await userService.create(req.body);
  res.status(201).json(data);
}

// services/userService.js
async create(userData) {
  await this.validate(userData);
  const user = await userRepository.create(userData);
  await emailService.sendWelcome(user.email);
  return user;
}

// repositories/userRepository.js
async create(userData) {
  return await db.query(
    'INSERT INTO users (name, email) VALUES (?, ?)',
    [userData.name, userData.email]
  );
}

Actividades

🔍 Actividad 1: Análisis de código existente

Analiza el siguiente código de una API REST que no sigue una arquitectura por capas. Identifica al menos 3 problemas de organización y explica cómo afectan el mantenimiento del proyecto. 

// index.js - API sin arquitectura
const express = require('express');
const app = express();
const mysql = require('mysql2');

app.use(express.json());

app.get('/products', (req, res) => {
  const connection = mysql.createConnection({...});
  connection.query('SELECT * FROM products', (err, results) => {
    if (err) {
      res.status(500).json({ error: err.message });
    } else {
      const filtered = results.filter(p => p.price > 100);
      res.json(filtered);
    }
  });
});

app.post('/products', (req, res) => {
  const connection = mysql.createConnection({...});
  connection.query(
    'INSERT INTO products SET ?',
    req.body,
    (err, result) => {
      if (err) {
        res.status(500).json({ error: err.message });
      } else {
        res.status(201).json({ id: result.insertId });
      }
    }
  );
});

app.listen(3000);
