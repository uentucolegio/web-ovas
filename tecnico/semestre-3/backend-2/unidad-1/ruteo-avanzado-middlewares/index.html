¡Bienvenido al mundo del Ruteo Avanzado! 🚀

Imagina que estás organizando una fiesta enorme 🎉. Tienes cientos de invitados, cada uno con necesidades diferentes: unos quieren música, otros comida, otros simplemente conversar. Si intentas atender a todos al mismo tiempo sin organización, ¡será un caos! 😅

En el desarrollo backend pasa algo similar. Cuando tu API crece y empieza a recibir miles de solicitudes, necesitas herramientas especiales para organizar el flujo de información. Aquí es donde entran en juego el ruteo avanzado y los middlewares 🛠️.

Anteriormente aprendiste sobre la arquitectura por capas, que es como tener diferentes departamentos en una empresa. Ahora vamos a dar el siguiente paso: aprenderás a organizar las rutas de tu API como un experto 🏗️, a validar datos antes de que lleguen a tu sistema 🔒, a registrar eventos importantes para monitorear todo lo que sucede 📊, y a manejar errores de forma profesional cuando algo sale mal 🚑.

✨ Al finalizar este OVA, serás capaz de construir APIs robustas y escalables que cualquier empresa querrá tener. ¡Vamos a convertirte en un maestro del backend! 🚀 🎯

Objetivos de aprendizaje 🎯

  • 🧠 Comprender el funcionamiento del sistema de ruteo avanzado en aplicaciones backend y su importancia para la organización de una API REST.
  • 💡 Implementar middlewares para realizar procesos de validación, registro de eventos (logging) y control de solicitudes antes de su procesamiento por los controladores.
  • 🔧 Diseñar un mecanismo centralizado de manejo de errores que permita responder de forma consistente ante situaciones excepcionales durante la ejecución de la aplicación.

Un middleware es como un guardia de seguridad 🛡️ que está entre la solicitud del cliente y tu controlador. Puede revisar, modificar o rechazar la solicitud antes de que llegue a su destino final.

🎮 Misión 3: Identifica el middleware

¿Qué middleware necesitarías para verificar que un usuario tenga permiso de administrador?

En Express.js, los middlewares se clasifican según cuándo se ejecutan:

1. Middleware a nivel de aplicación 🌐

Se ejecutan para TODAS las rutas de tu aplicación. Útil para logging global, manejo de errores, etc.

app.use((req, res, next) => {
  console.log('Solicitud recibida:', req.url);
  next();
});

2. Middleware a nivel de router 🛣️

Se ejecutan solo para rutas específicas. Perfecto para validar datos de un módulo en particular.

router.use(validarDatos);
router.get('/usuarios', obtenerUsuarios);

3. Middleware a nivel de ruta 📍

Se ejecutan solo para una ruta específica. Ideal para validaciones muy específicas.

app.get('/usuarios', 
  autenticar, 
  autorizarAdmin, 
  obtenerUsuarios
);

🎮 Misión 4: Clasifica el middleware

¿Qué tipo de middleware usarías para registrar TODAS las solicitudes que llegan a tu API?

Cuando algo sale mal en tu aplicación, necesitas manejarlo de forma profesional. El manejo centralizado de errores te permite responder de forma consistente ante cualquier situación excepcional 🚑.

⚠️ ¿Por qué es importante?

Imagina que cada ruta maneja los errores de forma diferente. Un usuario podría recibir mensajes de error confusos o, peor aún, información sensible del servidor. ¡El manejo centralizado soluciona esto! 🔒

Un middleware de error en Express tiene 4 parámetros en lugar de 3:

app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({
    error: 'Algo salió mal',
    mensaje: err.message
  });
});

Las mejores prácticas incluyen:

  • 🔒 Nunca expongas información sensible en producción
  • 📝 Registra todos los errores para análisis posterior
  • 🎯 Proporciona mensajes de error claros para el usuario
  • 🔄 Usa códigos de estado HTTP apropiados (400, 401, 403, 404, 500, etc.)

🔍 Actividad 1: Análisis de rutas

Analiza una API REST existente (puede ser un proyecto que hayas desarrollado anteriormente) e identifica todas las rutas que están definidas en un solo archivo. Clasifica estas rutas por recurso (usuarios, productos, pedidos, etc.) y crea un diagrama de cómo las organizarías usando ruteo avanzado.

📝 Producto esperado: Un diagrama o documento que muestre la organización propuesta de rutas, con al menos 3 grupos de rutas diferentes.

🛡️ Actividad 2: Implementación de middleware de validación

Crea un middleware de Express que valide que el cuerpo de una solicitud POST contenga los campos obligatorios "nombre" y "email". El middleware debe rechazar la solicitud con un código 400 si faltan estos campos, y pasar al siguiente middleware si están presentes.

📝 Producto esperado: Código JavaScript del middleware de validación funcional, con pruebas de funcionamiento.

🚑 Actividad 3: Manejo centralizado de errores

Implementa un middleware de manejo de errores centralizado en una aplicación Express. Este middleware debe: (1) registrar el error en consola, (2) devolver una respuesta JSON con un mensaje apropiado, (3) usar diferentes códigos de estado según el tipo de error (400 para errores de validación, 401 para no autenticado, 403 para no autorizado, 404 para no encontrado, 500 para errores del servidor).

📝 Producto esperado: Código del middleware de errores con al menos 4 tipos de errores diferentes manejados.
