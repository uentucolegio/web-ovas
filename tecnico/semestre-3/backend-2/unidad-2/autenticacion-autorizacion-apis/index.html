Autenticación y autorización: el bouncer digital 🛡️

Imagina que entras a tu app favorita de música 🎧. Tú eres tú, nadie más puede escuchar tu playlist privada ni cambiar tu plan de pago. Pero si cualquiera pudiera hacer eso sin verificar quién es, ¡el caos estaría servido! En el mundo del backend, la autenticación es como mostrar tu documento en la entrada de un concierto: confirma quién eres. La autorización decide si puedes entrar al VIP, al backstage o solo a la zona general 🎫.

En este OVA vas a descubrir cómo proteger una API REST para que cada usuario acceda solo a lo que le corresponde. Aprenderás a construir login, registro, sesiones, tokens JWT y un sistema de roles y permisos que hará tu backend mucho más robusto. ¡Prepárate para convertirte en el guardián de las APIs! 🔐

✨ Al finalizar este OVA serás capaz de diseñar un sistema de acceso seguro: sabrás quién entra y qué puede hacer dentro de tu aplicación. 🚀

Objetivos de aprendizaje

  • 🧠 Comprender la diferencia entre autenticación y autorización, identificando el papel que desempeña cada proceso en la seguridad de una API REST.
  • 💡 Analizar el funcionamiento de los mecanismos más utilizados para autenticar usuarios, incluyendo el uso de sesiones y tokens.
  • 🔧 Implementar esquemas básicos de control de acceso mediante roles y permisos para restringir el uso de los recursos de una aplicación.

¿Cómo sabe el servidor que ya iniciaste sesión? Hay dos grandes estrategias. Con sesiones el servidor guarda un ID en memoria o base de datos. Con tokens (como JWT) el servidor firma un mensaje y te lo entrega; tú lo envías en cada petición. ¿Cuál elegir? Depende del proyecto.

🍪 Sesiones

  • El servidor almacena el estado.
  • Rápidas de invalidar (cerrar sesión).
  • Ideal para apps monolíticas.
  • Requiere compartir estado en múltiples servidores.

🪙 Tokens JWT

  • El cliente guarda el token.
  • Escalan bien en APIs y microservicios.
  • Contienen cabecera, payload y firma.
  • Hasta expirar, son válidos (cuidado con robos).

💡 Tip

Muchas apps modernas combinan ambos: JWT para la API y sesiones para el panel de administración.

Una tienda online no puede permitir que un cliente vea el panel de administración. Ahí entran los roles (grupos de usuarios) y los permisos (acciones permitidas). Diseñar esto bien evita errores costosos y escándalos de seguridad.
