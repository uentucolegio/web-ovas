☁️ Seguridad en la nube (IaaS, PaaS, SaaS)

La adopción de servicios en la nube ha cambiado la forma en que se despliegan y administran las aplicaciones web. En lugar de administrar servidores físicos, las organizaciones contratan capacidades de cómputo, plataformas de desarrollo o software completo a proveedores como AWS, Microsoft Azure o Google Cloud. Sin embargo, migrar a la nube no elimina la responsabilidad de seguridad: la redistribuye.

Uno de los conceptos más importantes para trabajar de forma segura en la nube es el modelo de responsabilidad compartida, que define qué aspectos de la seguridad corresponden al proveedor y cuáles siguen siendo responsabilidad del cliente. Desconocer esta división es una de las causas más comunes de incidentes de seguridad en entornos cloud, como la exposición pública de datos almacenados en buckets mal configurados.

☁️ La nube no es intrínsecamente insegura ni intrínsecamente segura: su nivel de seguridad depende, en gran medida, de cómo la configura quien la utiliza. 🔧

🎯 Objetivos de aprendizaje

  • 🧠 Diferenciar los modelos de servicio en la nube IaaS, PaaS y SaaS.
  • 💡 Comprender el modelo de responsabilidad compartida entre el proveedor de nube y el cliente.
  • 🔧 Identificar los riesgos de seguridad más frecuentes asociados a una configuración incorrecta en la nube.
  • 📦 Aplicar buenas prácticas de gestión de identidades y accesos (IAM) en un entorno en la nube.

En Infraestructura como Servicio (IaaS), el proveedor ofrece recursos de cómputo, almacenamiento y red virtualizados, mientras que el cliente administra el sistema operativo, el middleware y las aplicaciones (por ejemplo, AWS EC2 o Azure Virtual Machines). En Plataforma como Servicio (PaaS), el proveedor gestiona además el sistema operativo y el entorno de ejecución, y el cliente solo despliega su código (por ejemplo, Heroku o Azure App Service). En Software como Servicio (SaaS), el proveedor gestiona toda la pila tecnológica y el cliente únicamente utiliza la aplicación final (por ejemplo, Gmail o Microsoft 365).

IaaS

El cliente administra sistema operativo, middleware y aplicaciones. Ej.: AWS EC2, Azure VM.

PaaS

El cliente solo despliega su código; el proveedor gestiona el entorno de ejecución. Ej.: Heroku.

SaaS

El proveedor gestiona toda la pila; el cliente solo usa la aplicación. Ej.: Gmail, Microsoft 365.

A medida que se avanza de IaaS a SaaS, el proveedor asume una mayor parte de la responsabilidad de seguridad, pero el cliente nunca queda completamente exento: la gestión de identidades, el control de acceso a los datos y la configuración correcta de los servicios contratados siguen siendo, en la mayoría de los modelos, responsabilidad del cliente.

⚖️ El proveedor es responsable de la seguridad de la nube (infraestructura física, red, virtualización), mientras que el cliente es responsable de la seguridad en la nube (datos, identidades, configuración).

La mayoría de los incidentes de seguridad en la nube no se originan por fallas del proveedor, sino por errores de configuración del cliente: recursos de almacenamiento expuestos públicamente, credenciales incluidas directamente en el código fuente, roles con permisos más amplios de los necesarios, o puertos de administración accesibles desde cualquier dirección de Internet.

🪣 Un bucket de almacenamiento configurado como público por error es, en la práctica, uno de los incidentes de exposición de datos más frecuentes reportados en entornos cloud.

La gestión de identidades y accesos (IAM, por sus siglas en inglés) permite definir qué usuarios, aplicaciones o servicios pueden acceder a qué recursos y con qué nivel de permisos. Aplicar el principio de mínimo privilegio implica otorgar únicamente los permisos estrictamente necesarios para cada rol o función, evitando el uso de cuentas con privilegios administrativos para tareas rutinarias.

Ejemplo de una política IAM restrictiva (formato JSON, estilo AWS) que solo permite lectura sobre un bucket:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::mi-bucket-academico/*"
    }
  ]
}
Código 1. Política IAM que restringe el acceso a un bucket únicamente a operaciones de lectura.

Adoptar de forma sistemática un conjunto de buenas prácticas reduce significativamente el riesgo de incidentes en entornos cloud, independientemente del proveedor o modelo de servicio contratado.

Configuración privada por defecto

Los recursos de almacenamiento y bases de datos deben crearse privados y exponerse solo cuando sea estrictamente necesario.

Gestión de credenciales

Nunca incluir claves de acceso directamente en el código fuente; usar variables de entorno o gestores de secretos.

Autenticación multifactor

Habilitar MFA para todas las cuentas con privilegios administrativos en la consola del proveedor.

Auditoría continua

Revisar periódicamente los permisos IAM asignados y eliminar los que ya no sean necesarios.

✍️ Actividades

🧩 Actividad 1: Análisis del modelo de responsabilidad (Individual)

Seleccione un servicio en la nube que utilice habitualmente (correo, almacenamiento, hosting) e identifique si corresponde a un modelo IaaS, PaaS o SaaS. Elabore una tabla que indique qué aspectos de la seguridad son responsabilidad del proveedor y cuáles son responsabilidad suya como usuario.

📝 Producto esperado: tabla comparativa de responsabilidades entre el proveedor y el usuario para el servicio elegido.

🔎 Enfoque: identificación clara del modelo de servicio y del reparto de responsabilidades.

👥 Actividad 2: Configuración segura de un bucket de almacenamiento (Grupal)

En grupos de máximo tres integrantes, utilicen la capa gratuita de un proveedor en la nube para crear un bucket de almacenamiento. Configúrenlo de manera que sea privado por defecto y elaboren una política de acceso que solo permita la lectura de un archivo específico desde una cuenta autorizada. Documenten el proceso con capturas de pantalla.

📝 Producto esperado: evidencia (capturas de pantalla) del bucket configurado como privado y de la política de acceso aplicada.

👥 Modalidad: trabajo colaborativo en equipos de máximo tres estudiantes.
