🏗️ Cómo se estructura una app en la nube

Cuando usas una aplicación web, ves una pantalla, haces clic en botones y los datos aparecen casi instantáneamente. 🖥️ Pero detrás de esa experiencia aparentemente simple hay una cadena de componentes que trabajan juntos: un servidor que recibe tu petición, una base de datos que busca la información, una API que empaqueta la respuesta y un frontend que la presenta de forma legible. Esa cadena no vive en un solo computador: en la nube, cada pieza puede estar en un servicio distinto, en una zona distinta, gestionada de forma independiente.

Entender cómo se estructura una aplicación en la nube es una de las habilidades más útiles que puedes desarrollar como programador web. 🧩 No porque tengas que diseñar infraestructuras complejas desde el primer día, sino porque esa comprensión te permite tomar mejores decisiones cuando eliges dónde desplegar tu backend, cómo conectarlo con la base de datos o por qué tu aplicación responde lento en algunos contextos.

Aquí vas a conocer las arquitecturas más comunes con las que se construyen aplicaciones web en la nube y las herramientas con las que los desarrolladores y equipos de infraestructura las gestionan día a día. 🛠️

✨ Al terminar vas a poder leer un diagrama de arquitectura cloud y entender qué hace cada pieza. ¡Manos a la obra! 🚀

Objetivos de aprendizaje

  • 🧠 Describir las arquitecturas básicas de aplicaciones web en la nube, identificando los componentes que conforman una solución típica (frontend, backend, base de datos y red) e interpretando diagramas de arquitectura cloud.
  • 🛠️ Reconocer las herramientas con las que los desarrolladores interactúan con los proveedores de nube (consola web, CLI y SDK), como punto de partida para trabajar con estas plataformas.

Tu app funciona con 10 usuarios. Pero, ¿y si mañana llegan 10.000 de golpe porque se hizo viral? 🚀 Ahí entra el escalado, y hay dos formas de hacerlo:

⬆️ Escalado vertical

Hacer más grande el mismo servidor (más CPU, más RAM). Simple, pero tiene un techo físico y un solo punto de fallo.

➡️ Escalado horizontal

Añadir más servidores y repartir el tráfico entre ellos con un balanceador de carga. Es como abrir más cajas en un supermercado. 🛒

Simula un pico de tráfico: llegan usuarios y tú decides cuántos servidores levantar. Reto: mantén la app en línea con 12.000 usuarios. 👇

Separar una app en capas es un primer paso. El siguiente gran debate de la industria es: ¿un solo bloque grande (monolito) o muchos servicios pequeños e independientes (microservicios)? 🤔 No hay un ganador absoluto: cada uno tiene ventajas. Netflix usa microservicios; muchas startups exitosas empezaron (y siguieron) con un monolito bien hecho.

Clasifica cada característica: ¿describe a un monolito o a microservicios? Cada acierto suma 10 puntos. 👇

Actividades

Completa estas misiones para poner en práctica lo aprendido. Marca cada una al terminarla y observa cómo avanza tu progreso. 🏆

🏁 Progreso de misiones: 0 / 5 completadas

☁️ Actividad 1: Laboratorio guiado — Tu primer recurso en la nube

Parte A — Crear la cuenta: ve a aws.amazon.com/free y crea una cuenta gratuita (pide tarjeta para verificar identidad, pero no cobra dentro del free tier; si no tienes tarjeta, usa Google Cloud o solicita AWS Academy a tu docente). Toma captura del panel principal. Parte B — Explorar la consola: busca y abre EC2, S3 y RDS (sin crear nada) y anota qué gestiona cada servicio; toma captura de cada uno. Parte C — Cambiar de región: cambia la región activa a South America (São Paulo) — sa-east-1, observa si algo cambia y responde por qué convendría esta región para usuarios en Colombia.

📝 Producto esperado: capturas de las tres partes + respuestas escritas a las preguntas de cada sección.

📐 Actividad 2: Diagrama de arquitectura de una aplicación conocida

Elige una app web que uses con frecuencia (red social, streaming, tienda en línea, etc.) e intenta reconstruir su arquitectura en la nube con un diagrama. Propón una arquitectura posible que tenga sentido para ese tipo de app, identificando: capa de frontend (¿dónde vivirían los archivos estáticos?), capa de backend/API (¿en qué tipo de servicio correría?), base de datos (¿relacional o NoSQL? ¿gestionada?) y al menos un componente adicional (CDN, balanceador, caché o cola de mensajes) con justificación.

📝 Producto esperado: diagrama + párrafo de justificación para cada componente elegido.

🧰 Actividad 3: Comparación de herramientas de interacción

Completa una tabla comparativa de Consola web, CLI y SDK con estos criterios: ¿cómo se accede?, ¿es automatizable?, ¿cuándo conviene usarla?, ¿qué conocimiento previo requiere? y un ejemplo de tarea que harías con cada herramienta. Luego responde: si tuvieras que desplegar tu proyecto web cada vez que haces un cambio, ¿cuál herramienta usarías y por qué?

📝 Producto esperado: tabla completa + respuesta justificada.

⌨️ Actividad 4: Laboratorio — Primeros comandos con AWS CloudShell

Desde la consola de AWS abre CloudShell (ícono >_ en la barra superior; no requiere instalar nada). Ejecuta y observa el resultado de:

aws sts get-caller-identity
aws ec2 describe-regions --query "Regions[].RegionName" --output table
aws s3 ls

Toma captura de los tres comandos con sus resultados y responde: ¿qué diferencia notaste entre la consola web y la CLI? ¿Para qué tareas sería más útil la CLI? Si quisieras automatizar el despliegue de tu app en cada cambio, ¿usarías consola o CLI? ¿Por qué?

📝 Producto esperado: capturas de los tres comandos + respuestas escritas.

🧩 Actividad 5: Cuestionario de comprensión

Responde individualmente: ¿qué problema resuelve la arquitectura de tres capas frente a la monolítica? Describe qué hace cada capa. ¿Para qué sirve un balanceador de carga y cuándo lo necesitarías? ¿Cuál es la diferencia entre usar la consola web y la CLI para crear un servidor? ¿Para qué usarías el SDK de un proveedor en tu código Node.js (ejemplo concreto)? Si tuvieras que desplegar el backend que hiciste en Programación Web I, ¿qué tres componentes de arquitectura en la nube necesitarías como mínimo?

📝 Producto esperado: respuestas escritas de mínimo 3 líneas por pregunta.

Recursos para profundizar

Para ampliar tu conocimiento, te recomendamos explorar los siguientes recursos:

  • Excalidraw

    Herramienta gratuita en línea para crear diagramas de arquitectura con estilo de boceto. No requiere registro. Ideal para la Actividad 2.

    Ir al recurso

  • draw.io / diagrams.net

    Editor de diagramas gratuito con plantillas específicas para arquitecturas en la nube (AWS, Azure, GCP) e íconos oficiales de los proveedores.

    Ir al recurso

  • AWS Architecture Center

    Biblioteca de diagramas de referencia de arquitecturas reales en AWS. Útil para ver cómo se estructura una app web o un sistema de microservicios en producción.

    Ir al recurso

  • AWS Free Tier

    Página oficial con todos los servicios del nivel gratuito de AWS, sus límites y duración. Indispensable antes de usar la consola para no generar costos.

    Ir al recurso

  • AWS CloudShell

    Terminal en el navegador integrada en la consola de AWS. No requiere instalación. Usada directamente en la Actividad 4 (requiere cuenta AWS).

    Ir al recurso
