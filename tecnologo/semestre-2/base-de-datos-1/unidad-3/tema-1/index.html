Del diagrama a la base de datos real 🏗️

Hasta ahora todo tu diseño —entidades, tablas, claves y relaciones— vive solo en el papel o en un diagrama. 📝 ¡Llegó el momento de darle vida! Vamos a materializarlo dentro de un SGBD (Sistema de Gestión de Bases de Datos) usando el idioma que estos sistemas entienden: SQL (Structured Query Language). 💬

SQL es el lenguaje estándar que usan prácticamente todos los SGBD relacionales: MySQL, PostgreSQL, SQL Server, Oracle, SQLite y muchos más. 🌍 Cada motor tiene pequeñas variaciones en su sintaxis (llamadas dialectos), pero el núcleo del lenguaje es casi idéntico en todos gracias a los estándares ISO/IEC. SQL se divide en subconjuntos según lo que hace cada instrucción: el DDL (Data Definition Language), que estudiarás en este tema, se encarga de definir y modificar la estructura de la base de datos (tablas, columnas y restricciones), mientras que el DML (Data Manipulation Language) trabaja con los datos que viven dentro de esa estructura. 🧱

✨ Al terminar este tema vas a crear, modificar y eliminar tablas con SQL como lo hace un desarrollador de verdad, sabiendo exactamente qué instrucción usar… y cuál nunca ejecutar a la ligera. 🚀

Objetivos de aprendizaje

  • 🧠 Reconocer el lenguaje de definición de datos (DDL) como el subconjunto de SQL responsable de crear y modificar la estructura de una base de datos.
  • 🏗️ Implementar en SQL, mediante la instrucción CREATE TABLE, el esquema relacional diseñado durante la Unidad 2, incluyendo tipos de datos, claves y restricciones.
  • 🛠️ Modificar la estructura de tablas existentes utilizando la instrucción ALTER TABLE, sin perder la información ya almacenada.
  • 💣 Aplicar correctamente la instrucción DROP para eliminar objetos de la base de datos, reconociendo los riesgos asociados a su uso.

SQL nació en los años 70 en IBM con el nombre de SEQUEL y hoy es uno de los lenguajes más usados del planeta. 🌎 Piensa en una base de datos como un supermercado: alguien construye las estanterías, alguien acomoda los productos, alguien los busca y alguien decide quién puede entrar a la bodega. En SQL, cada uno de esos trabajos tiene su propia familia de instrucciones: 👇

🏗️ DDL — Definición

Construye y remodela las estanterías: la estructura.

CREATE · ALTER · DROP · TRUNCATE

📦 DML — Manipulación

Pone, cambia o saca productos: los datos.

INSERT · UPDATE · DELETE

🔍 DQL — Consulta

Busca y muestra lo que hay en las estanterías.

SELECT

🔐 DCL — Control

Decide quién puede entrar y qué puede tocar.

GRANT · REVOKE

🔄 TCL — Transacciones

Confirma o deshace un grupo de cambios.

COMMIT · ROLLBACK

🐬 Dato clave: los ejemplos de este tema usan la sintaxis de MySQL. Si trabajas con PostgreSQL o SQL Server, la idea es la misma, pero algunas palabras cambian. ¡Siempre revisa la documentación oficial de tu motor! 📖

💸 ¿Por qué el dinero va en DECIMAL y no en FLOAT?

Los tipos FLOAT y DOUBLE guardan números aproximados: para el computador, 0.1 + 0.2 da 0.30000000000000004 😱. Con plata eso es inaceptable. DECIMAL(10,2) guarda el valor exacto: hasta 10 dígitos, 2 de ellos decimales.

▶️ Ver recurso

Una clave foránea se declara dentro del mismo CREATE TABLE con FOREIGN KEY ... REFERENCES. Y aquí va la regla de oro: ⚠️ la tabla "mamá" (la referenciada) debe existir antes que la tabla que la referencia. Es como inscribirte a un curso: primero tienen que existir tú y el curso. 🎓

CREATE TABLE matricula (
    id_estudiante INT NOT NULL,
    id_curso      INT NOT NULL,
    PRIMARY KEY (id_estudiante, id_curso),   -- clave primaria compuesta
    FOREIGN KEY (id_estudiante) REFERENCES estudiante(id_estudiante)
        ON DELETE CASCADE,
    FOREIGN KEY (id_curso) REFERENCES curso(id_curso)
        ON DELETE RESTRICT
);

CASCADE 🌊

Borras al estudiante y se borran sus matrículas. El cambio "cae en cascada".

RESTRICT ⛔

No te deja borrar el curso mientras tenga estudiantes inscritos.

SET NULL 🕳️

Borras el departamento y el empleado queda "sin departamento" (NULL).

SET DEFAULT ⚙️

Pone el valor por defecto de la columna. 👀 Ojo: MySQL (InnoDB) lo reconoce pero no lo permite; PostgreSQL sí.

DROP elimina un objeto completo: una tabla, una base de datos o una restricción, con estructura y datos. CREATE TABLE cliente (
    id_cliente      CHAR(4) PRIMARY KEY,
    nombre_cliente  VARCHAR(100) NOT NULL,
    telefono        VARCHAR(15),
    correo          VARCHAR(120),
    ciudad_cliente  VARCHAR(60),
    direccion       VARCHAR(150)
);

CREATE TABLE producto (
    id_producto      CHAR(4) PRIMARY KEY,
    nombre_producto  VARCHAR(100) NOT NULL,
    descripcion      VARCHAR(150),
    precio_unitario  DECIMAL(10,2) NOT NULL,
    stock            INT,
    categoria        VARCHAR(50)
);

CREATE TABLE factura (
    id_factura   CHAR(4) PRIMARY KEY,
    fecha        DATE NOT NULL,
    id_cliente   CHAR(4) NOT NULL,
    metodo_pago  VARCHAR(30),
    subtotal     DECIMAL(10,2),
    total        DECIMAL(10,2),
    FOREIGN KEY (id_cliente) REFERENCES cliente(id_cliente)
);

CREATE TABLE detalle_factura (
    id_factura       CHAR(4),
    id_producto      CHAR(4),
    cantidad         INT NOT NULL,
    precio_unitario  DECIMAL(10,2),
    descuento        DECIMAL(5,2),
    subtotal         DECIMAL(10,2),
    PRIMARY KEY (id_factura, id_producto),   -- clave compuesta
    FOREIGN KEY (id_factura)  REFERENCES factura(id_factura),
    FOREIGN KEY (id_producto) REFERENCES producto(id_producto)
);
