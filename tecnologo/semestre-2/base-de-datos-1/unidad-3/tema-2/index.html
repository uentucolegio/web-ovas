¡Hora de llenar tu base de datos! 📥

Con el DDL construiste la estructura de tu base de datos: tablas, columnas, tipos de datos, claves primarias, claves foráneas y restricciones. 🏗️ Pero una base de datos recién creada está completamente vacía: es apenas un "esqueleto" sin información real. 💀 Para que un sistema de software sea útil hay que poder insertar información nueva, modificar la que ya existe cuando cambian las circunstancias y eliminar la que ya no se necesita. Esas tres operaciones son el corazón del DML (Data Manipulation Language). 💚

A diferencia del DDL, que cambia la estructura, el DML trabaja siempre sobre el contenido de las tablas, es decir, sobre las tuplas (filas). Sus tres instrucciones fundamentales son INSERT ➕ (agregar filas), UPDATE ✏️ (modificar filas) y DELETE 🗑️ (eliminar filas). Su sintaxis es sencilla, pero usarlas bien exige entender las restricciones que definiste en el DDL: el SGBD rechazará automáticamente cualquier operación que las viole, protegiendo así la integridad de tu información. 🛡️

✨ Al terminar este tema vas a darle vida a tus tablas: agregar, cambiar y borrar datos con precisión de cirujano… sin dañar ni un solo registro de más. 🚀

Objetivos de aprendizaje

  • 🧠 Reconocer el lenguaje de manipulación de datos (DML) como el subconjunto de SQL responsable de insertar, actualizar y eliminar información dentro de las tablas ya creadas.
  • ➕ Insertar registros en una tabla mediante la instrucción INSERT, respetando los tipos de datos, dominios y restricciones definidos en el DDL.
  • ✏️ Modificar información existente mediante la instrucción UPDATE, utilizando condiciones adecuadas para afectar únicamente los registros deseados.
  • 🗑️ Eliminar registros mediante la instrucción DELETE, comprendiendo los riesgos de omitir la cláusula WHERE y su relación con la integridad referencial.

⚠️ El WHERE es lo más importante (y lo más delicado) de un UPDATE. Si lo olvidas, el cambio se aplica a TODAS las filas de la tabla. 😱 Por eso herramientas como MySQL Workbench traen activado el modo de actualización segura (sql_safe_updates), que bloquea los UPDATE y DELETE sin un WHERE sobre una clave.

DELETE FROM elimina filas y deja la tabla intacta (no como DROP TABLE, que la demuele). Igual que en UPDATE, el WHERE decide cuáles filas se van… y si lo olvidas, ¡se van todas! 🧹

🔗 Si la fila que quieres borrar está siendo referenciada por una clave foránea, lo que pase depende de la política que definiste al crearla: RESTRICT ⛔ rechaza el borrado, CASCADE 🌊 borra también las filas relacionadas, SET NULL 🕳️ las deja sin referencia.

🤫 Secreto de la industria: el "borrado lógico". Muchas apps no hacen DELETE de verdad cuando "eliminas" tu cuenta: hacen un UPDATE usuario SET activo = FALSE (o guardan una fecha de eliminación). Así pueden recuperar tu cuenta si te arrepientes y conservar el historial de pedidos o facturas. Por eso algunas plataformas te dan 30 días para volver. 😉

🔎 Misión 1: El detective de instrucciones

Alguien dejó estas instrucciones listas para ejecutar sobre la tabla curso(id_curso, nombre, creditos, intensidad_horaria). Identifica cuáles tienen errores de sintaxis o pueden afectar registros que no deberían modificarse. 🕵️

-- Instrucción 1
INSERT INTO curso VALUES (6, 'Programación Web', 'tres', 144);

💡 'tres' es texto y la columna creditos es numérica (error de dominio). Además, no indicar la lista de columnas hace la instrucción frágil si la tabla cambia.

-- Instrucción 2
UPDATE curso SET creditos = 4;

💡 ¡No tiene WHERE! Todos los cursos quedarían con 4 créditos.

-- Instrucción 3
DELETE FROM curso WHERE id_curso = 3;

💡 Correcta: el WHERE apunta a un solo curso. (Si ese curso tuviera matrículas con RESTRICT, el SGBD lo rechazaría, pero la instrucción está bien escrita).

-- Instrucción 4
INSERT INTO curso (id_curso, nombre, creditos, intensidad_horaria)
VALUES (7, 'Redes de Computadores', 3, 144);

💡 Correcta: indica las columnas y cada valor respeta su tipo de dato.

-- Instrucción 1 corregida (créditos numérico y columnas explícitas)
INSERT INTO curso (id_curso, nombre, creditos, intensidad_horaria)
VALUES (6, 'Programación Web', 3, 144);

-- Instrucción 2 corregida (solo el curso deseado)
UPDATE curso SET creditos = 4 WHERE id_curso = 6;

-- Instrucciones 3 y 4: correctas, no requieren cambios
