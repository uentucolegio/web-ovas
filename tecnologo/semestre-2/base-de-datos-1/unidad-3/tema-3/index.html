¡Hazle preguntas a tus datos! 🔍

Con el DDL creaste la estructura de tu base de datos y con el DML aprendiste a insertar, actualizar y eliminar información. 💪 Pero la verdadera razón por la que existe una base de datos es poder sacarle información útil en cualquier momento para responder preguntas concretas: ¿cuáles productos tienen menos stock? 📦 ¿qué estudiantes tienen nota superior a 4.0? 🎓 ¿cuántos pedidos hubo el mes pasado? 🛒 Todas se responden con una sola instrucción, la más usada de todo SQL: SELECT.

SELECT pertenece al DQL (Data Query Language) y es la herramienta con la que un desarrollador o analista de datos pasa la mayor parte de su tiempo. 👩‍💻 A diferencia de INSERT, UPDATE y DELETE, SELECT nunca modifica los datos: solo los consulta y los muestra. Es una operación de "solo lectura", sin riesgo de dañar nada. 😌

Vas a construir consultas cada vez más completas: elegir columnas, filtrar filas con condiciones, ordenar y limitar resultados y, al final, resumir la información con funciones de agregación. 📊 Todo esto es la base indispensable para el último tema del curso, donde combinarás varias tablas con JOIN. 🔗

✨ Al terminar este tema vas a convertir cualquier pregunta de negocio en una consulta SQL que la responde en segundos. ¡Bienvenido al mundo de los analistas de datos! 🚀

Objetivos de aprendizaje

  • 🔍 Construir consultas SELECT para recuperar información específica de una o varias columnas de una tabla.
  • 🎯 Aplicar filtros mediante la cláusula WHERE utilizando operadores de comparación, lógicos y de patrón sobre distintos tipos de datos.
  • ↕️ Ordenar y limitar los resultados de una consulta mediante las cláusulas ORDER BY y LIMIT.
  • 📊 Aplicar funciones de agregación (COUNT, SUM, AVG, MAX, MIN) junto con GROUP BY y HAVING para resumir información de un conjunto de datos.

Tú escribes la consulta empezando por SELECT, pero el SGBD no la procesa en ese orden. 😮 Lógicamente, primero busca la tabla, luego filtra, agrupa, filtra grupos y recién ahí elige columnas y ordena. Entender esto resuelve dos misterios clásicos:

❓ ¿Por qué WHERE no acepta COUNT()?

Porque WHERE trabaja antes de que existan los grupos: todavía no hay nada que contar. Por eso existe HAVING.

❓ ¿Por qué ORDER BY sí acepta alias?

Porque ORDER BY ocurre después del SELECT, cuando el alias ya fue creado. En el WHERE el alias aún no existe.
