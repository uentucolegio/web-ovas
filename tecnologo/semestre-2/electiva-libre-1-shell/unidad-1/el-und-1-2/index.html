Comandos de navegación: pwd, ls, cd y tree

La navegación por el sistema de archivos es una competencia esencial para trabajar en entornos Linux. En tareas de administración de servidores, desarrollo de software o despliegue de aplicaciones, es frecuente localizar archivos, revisar configuraciones, consultar registros o gestionar proyectos desde la terminal.

Para ello, es indispensable conocer los comandos pwd, ls, cd y tree, los cuales permiten ubicarse, explorar y recorrer la estructura de directorios de forma eficiente y segura. El dominio de estas herramientas constituye la base para desenvolverse con confianza en entornos profesionales basados en Linux.

Navegación en Linux: pwd, ls, cd y tree

Aprende a ubicarte, explorar y navegar el sistema de archivos Linux usando comandos reales del proyecto pizzeria-web.

Tema 1 de 5

📍 Ubicarse con pwd

🏙️
Imagínalo así:

Si Linux fuera una ciudad, pwd te daría la dirección completa del edificio exacto donde estás, no una referencia aproximada.
Siempre sabrás dónde te encuentras en el sistema.

🖥️ Ejemplo — proyecto frontend

Andrés escribe pwd y obtiene su ubicación exacta:

$ pwd
/home/andres/proyectos/pizzeria-web/frontend-nextjs

Es una ruta absoluta porque comienza desde la raíz del sistema (/).

🔗 pwd vs pwd -P — enlaces simbólicos

En servidores con Nginx es frecuente encontrar enlaces simbólicos:

$ cd /var/www/tienda
$ pwd
/var/www/tienda
$ pwd -P
/srv/apps/tienda/releases/2026-06-30

pwd muestra la ruta lógica seguida; pwd -P muestra la ruta física real en disco. Útil cuando Nginx apunta a un release específico.

📌 Conocer tu ubicación exacta evita errores graves: editar archivos en la carpeta equivocada o borrar contenido fuera del proyecto correcto.

📋 Explorar contenido con ls

ls lista el contenido de un directorio. Es uno de los comandos más usados en el día a día de un desarrollador.

🖥️ Ejemplo — proyecto pizzeria-web 

$ ls
backend-laravel  frontend-nextjs  README.md  docker-compose.yml
⚙️ Opción 📋 Función
ls -l Muestra permisos, propietario, tamaño y fecha
ls -a Incluye archivos ocultos (p. ej. .env, .gitignore)
ls -h Muestra tamaños legibles (4.0K, 12M, 1.3G)
ls -t Ordena por fecha de modificación
ls -lah Combinación habitual: detalles + ocultos + tamaños legibles

🖥️ Ejemplo real — frontend Next.js 

$ cd /home/andres/proyectos/pizzeria-web/frontend-nextjs
$ ls -lah
drwxr-xr-x  12 andres andres 4.0K jun 30 09:12 .
drwxr-xr-x   4 andres andres 4.0K jun 30 08:40 ..
-rw-r--r--   1 andres andres  423 jun 29 18:10 .env.local
drwxr-xr-x   8 andres andres 4.0K jun 30 09:10 .git
-rw-r--r--   1 andres andres 1.1K jun 29 18:05 package.json
drwxr-xr-x 245 andres andres 8.0K jun 30 09:12 node_modules
🔐 Nota de seguridad: los archivos que empiezan con punto, como .env o .env.local, pueden contener claves y contraseñas del proyecto. No deben subirse a repositorios públicos ni compartirse en capturas.

📂 Navegar con cd

cd significa change directory. Permite moverse entre carpetas. Existe con ruta absoluta y relativa.

📍

Ruta absoluta

$ cd /home/andres/proyectos/pizzeria-web/backend-laravel
$ pwd
/home/andres/proyectos/pizzeria-web/backend-laravel
🔄

Ruta relativa

# Estando en pizzeria-web:
$ cd frontend-nextjs
⌨️ Comando 📋 Acción
cd .. Sube un nivel en el árbol de directorios
cd Vuelve al directorio personal (home)
cd - Regresa al directorio anterior (atajo muy útil)

🖥️ Ejemplo real — alternar entre configuración y despliegue

$ cd /etc/nginx/sites-available
$ cd /var/www/pizzeria-web/current
$ cd -
# Devuelve a /etc/nginx/sites-available

Esto ahorra tiempo cuando se alterna entre la configuración del servidor y los archivos desplegados.

📌 cd - es uno de los atajos más prácticos en el trabajo diario con servidores: te lleva de vuelta al directorio anterior sin reescribir la ruta.

🌲 Visualizar árbol con tree

tree dibuja la estructura jerárquica de carpetas y archivos. Útil para entender la forma general de un proyecto.

⚙️ Instalación

# Ubuntu / Debian
$ sudo apt install tree

# Fedora
$ sudo dnf install tree

⚠️ Usa sudo solo cuando el docente lo indique. Si no tienes permisos, trabaja en un equipo o laboratorio ya configurado.

🖥️ Ejemplo real — frontend Next.js 

$ tree -L 2 /home/andres/proyectos/pizzeria-web/frontend-nextjs
/home/andres/proyectos/pizzeria-web/frontend-nextjs
|-- app
|   |-- layout.tsx
|   |-- page.tsx
|-- public
|   |-- logo.svg
|-- src
|   |-- components
|   |-- lib
|-- package.json
|-- next.config.js
|-- tsconfig.json

La opción -L 2 limita la profundidad, evitando llenar la pantalla con node_modules.

⚙️ Opción 📋 Función
tree -L 2 Limita la profundidad a 2 niveles
tree -d Muestra solo directorios
tree -a Incluye archivos ocultos
tree -I 'node_modules|.git|dist' Excluye carpetas grandes o poco relevantes
💡 Usa tree -I 'vendor|node_modules|storage/logs' para ver la estructura limpia de un proyecto Laravel sin ruido.

🗂️ Organización del sistema de archivos Linux

Linux organiza todo desde una raíz única: /. A diferencia de Windows, no hay discos C:, D:; todo parte de la misma jerarquía.

📁 Ruta 📋 Descripción 💡 Ejemplo
/home Archivos personales; aquí viven los proyectos de desarrollo /home/andres/proyectos
/etc Configuraciones del sistema y de servicios /etc/nginx/nginx.conf
/var Datos variables: logs, cachés, colas /var/log/nginx/error.log
/srv Contenido servido por aplicaciones o servicios /srv/apps/pizzeria-api
/usr Programas y librerías del sistema /usr/bin/node
/tmp Archivos temporales del sistema /tmp/build-cache

🚀 Flujo de despliegue real del proyecto pizzeria-web

1️⃣
/home/andres/proyectos/pizzeria-web
El desarrollador trabaja y edita el código aquí.
2️⃣
/var/www/pizzeria-web/current
El frontend compilado se publica aquí.
3️⃣
/etc/nginx/sites-available/pizzeria-web
Nginx lee la configuración desde aquí.
4️⃣
/var/log/nginx/error.log
Los errores del servicio quedan registrados aquí.
💡 Cuando entiendes este mapa, dejas de memorizar carpetas aisladas y empiezas a interpretar Linux como un sistema coherente.
