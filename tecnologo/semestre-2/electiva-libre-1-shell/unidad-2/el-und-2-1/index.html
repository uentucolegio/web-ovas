Creación, copia, movimiento y eliminación de archivos

En el desarrollo de aplicaciones web es habitual trabajar de forma simultánea en un entorno local y en un servidor remoto. Un caso representativo es un proyecto de comercio electrónico, cuyo código fuente reside en una carpeta local como ~/proyectos/tienda-online/, pero cuyo despliegue final ocurre en un servidor Ubuntu que sirve los archivos estáticos desde /var/www/html/. En ese entorno no existe una interfaz gráfica: toda la gestión de archivos se realiza mediante la terminal.

Los comandos touch, mkdir, cp, mv y rm constituyen la base de esa gestión. Se utilizan de forma constante en tareas cotidianas del desarrollo web: crear la estructura inicial de un proyecto, copiar un archivo de configuración como .env.example para adaptarlo al entorno local, mover los archivos generados por un proceso de build hacia el directorio que sirve el servidor web, o eliminar carpetas de dependencias cuando es necesario reinstalarlas.

📁 ¡Gestionar archivos con criterio! Crear, copiar y mover son operaciones seguras, pero eliminar con rm es irreversible: verifica siempre la ruta antes de ejecutar. 🐧💻🛡️

📄 Creación de archivos y directorios: touch y mkdir

🏗️
Imagínalo así:

Antes de escribir una sola línea de código, touch y mkdir te permiten construir el esqueleto completo del proyecto: las carpetas y los archivos vacíos que luego llenarás de contenido. Es como levantar primero la estructura de una casa antes de amueblarla.

mkdir (make directory) crea uno o más directorios en la ruta especificada. touch crea un archivo vacío si no existe, o actualiza su fecha de modificación si ya existe. Ambos comandos permiten construir la estructura de carpetas y archivos que tendrá un proyecto.

Ejemplos con touch:

$ cd ~/proyectos/tienda-online
$ touch .env
$ touch src/utils/formatCurrency.js

Ejemplo con mkdir y la opción -p (“parents”), que crea toda la ruta de carpetas necesaria en un solo comando, incluso si las carpetas intermedias no existen todavía:

$ mkdir -p ~/proyectos/tienda-online/src/{controllers,routes,models}
# Crea src/ y dentro de ella controllers/, routes/ y models/,
# en una sola línea, gracias a la expansión de llaves {} de bash.

📋 ¿Qué hace cada comando?

Haz clic en cada fila para resaltarla:

⌨️ Comando 📄 Resultado
touch archivo.txt Crea un archivo vacío (o actualiza su fecha si ya existe)
mkdir carpeta Crea un directorio nuevo
mkdir -p a/b/c Crea toda la jerarquía de carpetas anidadas de una vez
mkdir -p src/{a,b} Usa la expansión de llaves {} para crear varias subcarpetas
Ejemplo aplicado — estructura inicial de un proyecto

Así se crea, en segundos, la estructura base de una API en Node.js antes de programar:

$ mkdir -p api-inventario/src/{controllers,routes,models}
$ cd api-inventario
$ touch package.json .env src/app.js
# Proyecto listo para empezar a programar
📌 Sin -p, si src/ no existiera todavía, mkdir src/controllers fallaría con el error “No such file or directory”. La opción -p evita ese problema creando las carpetas intermedias automáticamente.

📋 Copia de archivos y directorios: cp

El comando cp (copy) genera una copia independiente de un archivo o directorio en una nueva ubicación, o con un nuevo nombre. El archivo original permanece intacto: la copia resultante es un archivo separado, por lo que cualquier cambio posterior en uno de los dos no afecta al otro.

Un caso muy común en desarrollo web: los proyectos suelen incluir un archivo .env.example con variables de entorno de ejemplo, que cada desarrollador copia y llena con sus propias credenciales:

$ cp .env.example .env

Para copiar una carpeta completa (por ejemplo, para respaldar el resultado de un build antes de sobrescribirlo), se necesita la opción -r (“recursive”), porque por defecto cp no copia el contenido de directorios:

$ cp -r dist/ dist-backup-$(date +%F)

⚙️ Opciones importantes de cp

Haz clic en cada fila para resaltarla:

🔖 Opción 📄 Efecto
-r / -R Copia directorios de forma recursiva (obligatoria para carpetas)
-i Pide confirmación antes de sobrescribir un archivo existente
-v Modo verboso: muestra qué se está copiando
-u Solo copia si el origen es más nuevo que el destino (útil para sincronizar)
Ejemplo aplicado — respaldar la configuración de Nginx

Combinando varias opciones, se copia la configuración de Nginx antes de modificarla, con confirmación y modo verboso:

$ cp -iv /etc/nginx/sites-available/default /etc/nginx/sites-available/default.bak
📌 Recuerda: cp crea una copia independiente. Si copias una carpeta sin -r, obtendrás el error “omitting directory”. Las opciones -i y -v son buenas prácticas cuando el destino ya podría contener archivos.

🔀 Movimiento y renombrado: mv

✏️
La clave conceptual:

Desde el punto de vista del sistema de archivos, mover y renombrar son la misma operación: ambas consisten en actualizar la ruta asociada al archivo. Por esa razón, en Linux no existe un comando “rename” independiente.

⚖️ Mismo comando, dos usos

Mover a otra ubicación
$ mv ~/proyectos/tienda-online/dist/index.html /var/www/html/index.html

El archivo cambia de directorio: desaparece de la ruta original y aparece en la nueva. Ideal para publicar el build en la carpeta del servidor web.

VS
Renombrar en el mismo directorio
$ mv README.md README.old.md

Mismo comando, mismo directorio: el archivo conserva su contenido pero cambia de nombre. Así se “renombra” en Linux.

⚙️ Opciones útiles de mv

Igual que cp, mv admite -i (confirmación) y -v (verboso), y es buena práctica usarlas cuando el destino ya podría tener archivos con el mismo nombre:

$ mv -iv package.json package.json.bak
💡 Diferencia clave con cp: mv no crea una copia: el archivo desaparece de la ubicación original. Si necesitas conservar el original, usa cp en su lugar.

🗑️ Eliminación de archivos y directorios: rm

rm (remove) elimina archivos o directorios de forma permanente. A diferencia de la eliminación en una interfaz gráfica, rm no envía los archivos a una papelera de reciclaje: la operación se ejecuta de inmediato y, salvo que exista un respaldo previo, no es reversible.

Eliminar un archivo puntual:

$ rm notas-temporales.txt

Eliminar un directorio y todo su contenido (por ejemplo, para forzar una reinstalación limpia de dependencias de Node.js):

$ rm -rf node_modules

Aquí -r permite borrar directorios de forma recursiva, y -f (“force”) evita que se pregunte confirmación por cada archivo.

🔍 Desglose interactivo: haz clic en cada parte del comando

Antes de ejecutar una eliminación, comprende todas las partes del comando:

rm Comando
-r Opción
-f Opción
node_modules Objetivo

⚠️ Niveles de riesgo al eliminar

rm archivo → Elimina un archivo específico
rm -r directorio → Elimina el directorio y su contenido (pide confirmación)
rm -f archivo → Fuerza la eliminación sin preguntar
rm -rf / → ⚠️ PELIGROSO: puede eliminar todo el sistema
⚠️ El error más citado de la comunidad Linux: ejecutar rm -rf en la ruta equivocada (o con una variable vacía, como rm -rf $VAR/* cuando $VAR no está definida) puede borrar carpetas completas del sistema sin posibilidad de deshacer la acción.
