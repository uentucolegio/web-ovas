Redireccionamiento, tuberías y filtros básicos

El redireccionamiento, las tuberías y los filtros son herramientas fundamentales de la terminal de Linux que permiten gestionar y procesar información de forma eficiente. Estas funcionalidades se utilizan con frecuencia en tareas como el análisis de archivos de registro, la automatización de procesos, la administración de servidores y el despliegue de aplicaciones web.

Su dominio facilita el trabajo con proyectos reales desarrollados con tecnologías como Git, Node.js, Docker y Nginx, permitiendo combinar comandos como grep, sort, wc o cut mediante el operador | para obtener resultados de manera rápida y precisa.

¡Combina comandos con criterio! Las tuberías conectan herramientas pequeñas y especializadas, pero redirigir con > reemplaza el contenido de un archivo: verifica siempre el destino antes de ejecutar.

Tema 1 de 4

Redireccionamiento de entrada y salida: >, >> y <

Imagínalo así:

La mayoría de los comandos de Linux trabajan con tres flujos estándar: entrada estándar (stdin), salida estándar (stdout) y salida de errores (stderr). El redireccionamiento es como cambiar las tuberías de una casa: modificas el destino o el origen de esos flujos sin alterar el funcionamiento del comando.

Esta característica resulta especialmente útil para guardar resultados, registrar errores durante un despliegue o reutilizar información previamente almacenada.

Sintaxis y ejemplos:

$ tree ~/proyectos/tienda-online > estructura.txt
# Guarda el árbol del proyecto; si el archivo existe, lo reemplaza por completo
$ date >> despliegues.log
# Agrega la fecha al final del archivo, conservando el contenido anterior
$ wc -l < access.log
# wc lee su entrada desde el archivo en lugar del teclado y cuenta sus líneas

¿Qué hace cada operador?

Haz clic en cada fila para resaltarla:

⌨️ Sintaxis 📄 Resultado
comando > archivo Envía la salida estándar a un archivo; si existe, reemplaza su contenido
comando >> archivo Agrega la salida al final del archivo conservando el contenido (bitácoras)
comando < archivo El comando lee su información desde un archivo en lugar del teclado
Ejemplo aplicado — registrar la fecha de cada despliegue

Cada ejecución agregará una nueva línea al archivo, manteniendo una bitácora completa:

$ date >> despliegues.log
$ cat despliegues.log
# sáb 08 ago 2026 10:15:22
# sáb 08 ago 2026 11:42:07
Error común: ejecutar ls > package.json sobrescribe el archivo package.json, eliminando su contenido. Antes de utilizar >, verifique cuidadosamente el nombre del archivo destino.

Tuberías (pipes): el operador |

Imagínalo así:

Una tubería funciona como una cadena de montaje: la salida de un comando se conecta directamente con la entrada del siguiente, sin almacenar resultados intermedios en archivos temporales. Los datos fluyen directamente entre procesos.

El operador | conecta la salida de un comando con la entrada del siguiente. Este mecanismo constituye una de las características más potentes de Linux y permite construir procesos complejos mediante la combinación de herramientas pequeñas y especializadas.

Sintaxis y ejemplo:

$ comando1 | comando2
$ find ~/proyectos/tienda-online -name "*" | grep ".js"
# find lista todos los archivos; grep filtra únicamente los que contienen .js

Desglose interactivo: haz clic en cada parte de la tubería

Analiza cómo fluye la información en una tubería real de análisis de registros:

cat access.log Origen
| Tubería
grep "500" Filtro
sort | uniq -c Orden y conteo
Error común: no respetar el orden lógico de los comandos. Por ejemplo, grep package.json | ls no tiene efecto, porque ls no utiliza la entrada estándar.

Filtros de visualización: cat, less, head y tail

Los filtros procesan texto recibido desde un archivo o desde una tubería. Este grupo se especializa en mostrar contenido: completo, por partes o en tiempo real.

Ejemplos:

$ cat package.json
$ less /var/log/nginx/access.log
$ head -15 package-lock.json
$ tail -f /var/log/nginx/error.log

¿Qué hace cada filtro?

Haz clic en cada fila para resaltarla:

⌨️ Comando 📄 Qué hace
cat archivo Muestra (y concatena) el contenido de archivos; -n numera líneas y -b numera solo líneas con contenido
less archivo Recorre archivos largos sin cargarlos completamente en pantalla
head -20 archivo Muestra las primeras líneas del archivo (20 en este caso)
tail -f archivo Muestra las últimas líneas y monitorea el archivo en tiempo real
Ejemplo aplicado — monitorear errores de Nginx en vivo

Mientras pruebas tu aplicación, observa los errores a medida que ocurren:

$ tail -f /var/log/nginx/error.log
# La terminal queda "escuchando": cada nuevo error aparece al instante
Usa less para revisar logs, leer configuraciones extensas y examinar documentación sin saturar la pantalla: el archivo se carga por partes a medida que te desplazas.

Filtros de procesamiento: grep, sort, wc, uniq y cut

Este grupo de filtros busca, ordena, cuenta y extrae información de archivos o de la salida de otros comandos. Combinados con tuberías, permiten responder preguntas concretas sobre tus datos en segundos.

Ejemplos:

$ grep -rn "express" ~/proyectos/api-node
# Busca recursivamente referencias a Express en el proyecto
$ cut -d "," -f2 usuarios.csv
# Extrae únicamente los nombres de usuario de un archivo CSV
$ sort dependencias.txt
# Ordena alfabéticamente las líneas del archivo

¿Qué hace cada filtro?

Haz clic en cada fila para resaltarla:

⌨️ Comando 📄 Función ⚙️ Opciones frecuentes
grep patrón archivo Localiza líneas que contienen un texto determinado -i ignora mayúsculas, -n muestra número de línea, -r busca recursivamente
sort archivo Ordena líneas alfabética o numéricamente -r orden descendente, -n orden numérico
wc archivo Cuenta líneas, palabras y caracteres -l líneas, -w palabras, -c bytes
uniq Elimina líneas duplicadas consecutivas Se combina con sort para obtener valores únicos
cut -d "," -f2 archivo Extrae columnas de un archivo delimitado -d delimitador, -f campo a extraer
Ejemplo aplicado — contar cuántas veces aparece cada error

Combinando filtros en una tubería se obtiene un resumen estadístico del registro:

$ grep "ERROR" application.log | sort | uniq -c
# 3 ERROR: fallo la conexión a la base de datos
# 1 ERROR: timeout al consultar la API
Los filtros brillan cuando se combinan en tuberías: cada herramienta hace una sola cosa bien y los datos fluyen de una a otra, por ejemplo wc -l src/routes/index.js para contar las líneas del enrutador.
