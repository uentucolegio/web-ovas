Variables, parámetros y lectura de entrada en Bash

La terminal es una herramienta esencial en el desarrollo web, ya que muchas tareas de configuración, despliegue y mantenimiento se realizan en servidores Linux sin interfaz gráfica. Con ella, el desarrollador puede moverse entre directorios, crear y modificar archivos, revisar registros y trabajar con herramientas como Node.js, Nginx, Docker y Git, tanto en local como en servidores remotos mediante SSH.

El shell permite además automatizar tareas repetitivas mediante scripts que usan variables, parámetros y entradas del usuario, lo que reduce errores manuales y agiliza el trabajo. Un archivo como package.json o una carpeta dist dejan de escribirse a mano en cada ejecución: el script los recibe, los valida y actúa en consecuencia.

Por último, aunque la inteligencia artificial puede ayudar a generar scripts o detectar errores, no sustituye el conocimiento del sistema. El desarrollador debe entender qué hace cada comando antes de ejecutarlo, sobre todo en entornos con información importante.

🐧 ¡Automatiza con criterio! Un buen script recibe datos, los valida y avisa cuando algo falla: entender cada línea antes de ejecutarla es lo que separa una automatización útil de un error costoso. 💻🛡️

🐚 El shell Bash y los scripts

📋
Imagínalo así:

Un script es una receta de cocina: una lista de pasos escritos una sola vez que el shell ejecuta siempre igual, sin olvidar ni cambiar ningún ingrediente.

Bash es un intérprete de comandos ampliamente utilizado en sistemas Linux. Su nombre proviene de "Bourne Again Shell", una implementación compatible con el shell Bourne original. Además de ejecutar comandos individualmente, Bash permite almacenar instrucciones en archivos de texto llamados scripts.

Un script puede automatizar tareas como preparar una compilación de Node.js, revisar si existe un archivo package.json o generar un informe sobre el estado de un repositorio Git.

La línea shebang

Un script básico comienza normalmente con una línea llamada shebang, que indica qué intérprete debe utilizarse:

preparar-entorno.sh
#!/usr/bin/env bash echo "Preparación del proyecto frontend"

La expresión #!/usr/bin/env bash busca el ejecutable de Bash dentro de las rutas configuradas en el sistema. La instrucción echo muestra texto en la terminal.

Crear y ejecutar un script en un proyecto web

usuario@equipo:~$ mkdir -p ~/proyectos/tienda-react/scripts usuario@equipo:~$ cd ~/proyectos/tienda-react/scripts usuario@equipo:~$ touch preparar-entorno.sh usuario@equipo:~$ chmod +x preparar-entorno.sh usuario@equipo:~$ ./preparar-entorno.sh
  • La opción -p de mkdir crea también los directorios intermedios que no existan.
  • chmod +x agrega permiso de ejecución al archivo.
  • El prefijo ./ indica que el archivo debe ejecutarse desde el directorio actual.

Formas de ejecutar un script (haz clic en una fila)

Comando ¿Necesita +x? Cuándo usarlo
./preparar-entorno.sh Sí Uso habitual cuando el script ya tiene permiso de ejecución y shebang.
bash preparar-entorno.sh No Útil cuando el archivo todavía no tiene permiso de ejecución.
bash -n preparar-entorno.sh No Solo analiza la sintaxis: no ejecuta ninguna instrucción.

Errores frecuentes

Ejecutar el script sin ./
Ejecutar preparar-entorno.sh sin ./ puede producir un mensaje indicando que el comando no existe, porque el directorio actual normalmente no forma parte de la variable PATH.
Omitir la línea shebang
Sin shebang, el sistema puede utilizar un intérprete diferente al esperado.
Usar permisos excesivos con chmod 777
Expone innecesariamente los archivos. Para un script personal suele ser suficiente chmod +x.
Ejecutarlo desde el directorio equivocado
Puede provocar que el script no encuentre archivos como package.json o vite.config.js.

💲 Variables

Una variable de Bash almacena texto o valores que pueden utilizarse posteriormente durante la ejecución de un script. Se asigna sin espacios alrededor del signo igual y se consulta anteponiendo el símbolo $ al nombre. Las variables permiten evitar rutas repetidas y modificar fácilmente el comportamiento de una automatización.

#!/usr/bin/env bash PROJECT_DIR="$HOME/proyectos/portal-clientes" BUILD_DIR="$PROJECT_DIR/dist" echo "Proyecto: $PROJECT_DIR" echo "Directorio de compilación: $BUILD_DIR"

$HOME es una variable predefinida que contiene la ruta del directorio personal del usuario. Si el usuario se llama ana, por ejemplo, su valor podría ser /home/ana.

Asignación correcta e incorrecta

✅ Sin espacios alrededor del =
APP_NAME="portal-clientes" echo "$APP_NAME"
❌ Con espacios: Bash busca un comando
APP_NAME = "portal-clientes" # APP_NAME: command not found

Comillas dobles y rutas con espacios

Las comillas dobles son importantes cuando una ruta puede contener espacios:

PROJECT_DIR="$HOME/proyectos/portal clientes" echo "Revisando: $PROJECT_DIR"
⚠️
Sin comillas, Bash podría interpretar una ruta con espacios como varios argumentos independientes: portal y clientes serían dos rutas distintas.

Variables de entorno

Son valores disponibles para los procesos iniciados desde el shell. Pueden consultarse con printenv o env:

usuario@equipo:~$ printenv HOME usuario@equipo:~$ printenv PATH

Una variable puede exportarse para que también esté disponible dentro de programas ejecutados por el script:

usuario@equipo:~$ export NODE_ENV=production usuario@equipo:~$ npm run build

En este caso, NODE_ENV se entrega al proceso iniciado por npm.

🔢 Parámetros posicionales

Los parámetros posicionales permiten que un script reciba valores desde la línea de comandos. $0 representa el nombre del script, $1 el primer argumento, $2 el segundo y así sucesivamente. $# indica cuántos argumentos se recibieron y $@ representa todos los argumentos por separado.

revisar-archivo.sh
#!/usr/bin/env bash PROJECT_DIR="$1" TARGET_FILE="$2" printf 'Proyecto recibido: %s\n' "$PROJECT_DIR" printf 'Archivo recibido: %s\n' "$TARGET_FILE"

Se ejecutaría de esta forma (las comillas protegen la ruta si contiene espacios):

usuario@equipo:~$ ./revisar-archivo.sh "$HOME/proyectos/portal-clientes" package.json

Validar la cantidad de argumentos

Una validación básica evita que el script continúe cuando faltan argumentos:

#!/usr/bin/env bash if [ "$#" -ne 2 ]; then printf 'Uso: %s RUTA_PROYECTO ARCHIVO\n' "$0" >&2 exit 1 fi PROJECT_DIR="$1" TARGET_FILE="$2" printf 'Se revisará %s dentro de %s\n' "$TARGET_FILE" "$PROJECT_DIR"
  • [ "$#" -ne 2 ] comprueba que la cantidad de argumentos sea diferente de dos.
  • >&2 envía el mensaje al flujo de error estándar.
  • exit 1 finaliza el script indicando que ocurrió un error.

Código de salida de un comando

Para comprobar si una compilación terminó correctamente se consulta $?:

npm run build BUILD_STATUS=$? if [ "$BUILD_STATUS" -eq 0 ]; then printf 'La compilación terminó correctamente.\n' else printf 'La compilación falló con código %s.\n' "$BUILD_STATUS" >&2 exit "$BUILD_STATUS" fi
💡
Un código de salida igual a 0 representa normalmente éxito. Los valores diferentes de cero indican algún tipo de error.

⌨️ Lectura de entrada con read

El comando read obtiene información desde la entrada estándar y la almacena en una variable. Es útil para construir scripts interactivos, por ejemplo, cuando se necesita solicitar al usuario la ruta de un proyecto Node.js o elegir entre una compilación de desarrollo y una de producción.

#!/usr/bin/env bash printf 'Ingrese la ruta del proyecto Node.js: ' read -r PROJECT_DIR printf 'El proyecto seleccionado es: %s\n' "$PROJECT_DIR"

La opción -r evita que las barras invertidas sean interpretadas como caracteres especiales. Es una práctica recomendable para recibir rutas o texto introducido por el usuario.

Validación de la entrada

read -r -p "Ruta del proyecto: " PROJECT_DIR if [ ! -d "$PROJECT_DIR" ]; then printf 'La ruta no corresponde a un directorio existente.\n' >&2 exit 1 fi if [ ! -f "$PROJECT_DIR/package.json" ]; then printf 'No se encontró package.json en %s.\n' "$PROJECT_DIR" >&2 exit 1 fi printf 'El proyecto Node.js tiene una estructura válida.\n'
Prueba Significado
-d "$RUTA" Comprueba si existe un directorio.
-f "$RUTA" Comprueba si existe un archivo regular.
! -d "$RUTA" El signo ! niega la prueba: se cumple si el directorio no existe.

Las comillas son necesarias para que las rutas con espacios se procesen como un solo valor.

🗂️ Comandos de archivos en proyectos web

Los scripts de infraestructura suelen combinar comandos de Bash con herramientas habituales del ecosistema web. Estos son los ocho comandos básicos para moverse y trabajar con archivos dentro de un proyecto como portal-clientes.

Selecciona un comando para ver su función, un ejemplo y su precaución:

Opciones de ls

Opción Qué muestra
-l Información detallada: permisos, propietario y tamaño.
-a Incluye archivos ocultos, como .gitignore y .env.example.
-h Tamaños en un formato más legible (KB, MB).
🔎
No debe confundirse un archivo oculto con un archivo inexistente. En un proyecto Git, .gitignore y .git son elementos relevantes, aunque no aparezcan con un ls sencillo.

Eliminar con seguridad

Antes de eliminar una carpeta de compilación, conviene inspeccionarla:

usuario@equipo:~$ ls -la "$HOME/proyectos/portal-clientes/dist"

Una práctica más segura consiste en usar una variable y comprobar que no esté vacía:

BUILD_DIR="$HOME/proyectos/portal-clientes/dist" if [ -n "$BUILD_DIR" ] && [ -d "$BUILD_DIR" ]; then rm -rf -- "$BUILD_DIR" fi
🛑
-- indica que los argumentos siguientes no deben interpretarse como opciones. Aun así, la variable debe construirse de forma segura y no recibir valores arbitrarios sin validación.

🧩 Combinación de variables, parámetros y lectura de entrada

El siguiente script reúne los conceptos principales: solicita una ruta, comprueba que se trate de un proyecto Node.js, recibe una rama Git como parámetro opcional y crea un informe con información básica.

informe-proyecto.sh
#!/usr/bin/env bash set -u DEFAULT_PROJECT_DIR="$HOME/proyectos/portal-clientes" if [ "$#" -ge 1 ]; then PROJECT_DIR="$1" else read -r -p "Ruta del proyecto [$DEFAULT_PROJECT_DIR]: " PROJECT_DIR if [ -z "$PROJECT_DIR" ]; then PROJECT_DIR="$DEFAULT_PROJECT_DIR" fi fi BRANCH_NAME="${2:-main}" if [ ! -d "$PROJECT_DIR" ]; then printf 'No existe el directorio: %s\n' "$PROJECT_DIR" >&2 exit 1 fi if [ ! -f "$PROJECT_DIR/package.json" ]; then printf 'No se encontró package.json en: %s\n' "$PROJECT_DIR" >&2 exit 1 fi REPORT_DIR="$PROJECT_DIR/reports" REPORT_FILE="$REPORT_DIR/estado-proyecto.txt" mkdir -p "$REPORT_DIR" { printf 'Proyecto: %s\n' "$PROJECT_DIR" printf 'Rama solicitada: %s\n' "$BRANCH_NAME" printf 'Fecha de revisión: %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" if [ -d "$PROJECT_DIR/.git" ]; then git -C "$PROJECT_DIR" status --short else printf 'La ruta no contiene un repositorio Git.\n' fi } > "$REPORT_FILE" printf 'Informe creado en: %s\n' "$REPORT_FILE"

Errores frecuentes en scripts

🔤 Comillas

No colocar comillas alrededor de variables que contienen rutas.

🔢 Argumentos

Suponer que $1 siempre existe sin validar la cantidad de argumentos.

🗑️ Borrado

Utilizar rm -rf sin revisar previamente el valor de la variable.

📍 Rutas

Confundir una ruta relativa con una ruta absoluta.

📦 Node.js

Ejecutar npm run build en una carpeta que no contiene package.json.

🚦 Código de salida

Ignorar el código de salida de comandos como npm, git o docker.

🔐 Secretos

Guardar contraseñas, tokens o claves privadas en scripts versionados.

🤖 IA sin revisión

Pedir a una herramienta de IA un script destructivo y ejecutarlo sin revisar las rutas que modifica.

🤖 IA aplicada a infraestructura

Las herramientas de inteligencia artificial pueden asistir en tareas como la generación de una primera versión de un script, la explicación de un error de Bash, la propuesta de validaciones o la conversión de un procedimiento manual en una automatización.

Su uso debe estar acompañado por revisión técnica, porque una respuesta generada puede contener rutas incorrectas, opciones incompatibles o acciones peligrosas.

Cómo formular la solicitud

Una solicitud útil proporciona contexto suficiente y limita el alcance de la operación:

✅ Solicitud útil

Genera un script Bash para Ubuntu que reciba como primer parámetro la ruta de un proyecto Node.js. Debe verificar que exista package.json, crear el directorio reports dentro del proyecto y guardar allí el resultado de git status --short. No debe eliminar archivos ni ejecutar comandos con sudo. Incluye validación de parámetros y explica los riesgos.

❌ Solicitud deficiente

Haz un script para limpiar el servidor.

No especifica qué debe limpiarse, en qué ruta, con qué permisos ni qué archivos deben conservarse.
