Condicionales, ciclos y funciones básicas en Bash

La automatización mediante terminal constituye una competencia fundamental para el desarrollo web, especialmente cuando las aplicaciones deben ejecutarse, configurarse y mantenerse en entornos Linux. Herramientas como Git, Node.js, Nginx y Docker se administran frecuentemente desde la línea de comandos, y muchas tareas repetitivas pueden convertirse en scripts ejecutables que reduzcan errores y tiempos de operación.

Bash, uno de los intérpretes de comandos más utilizados en sistemas Linux, permite construir scripts capaces de tomar decisiones con if, repetir operaciones con for, while y until, y organizar instrucciones en funciones reutilizables. Estas capacidades permiten verificar que Node.js esté instalado, comprobar la existencia de archivos de configuración, procesar diferentes directorios de un proyecto, validar estados de Git o ejecutar acciones dependiendo del resultado de un proceso.

¡Automatiza con criterio! Un script bien construido valida antes de actuar: usa condiciones para comprobar archivos y directorios, ciclos para evitar repetir comandos y funciones para reutilizar tu trabajo.

Tema 1 de 5

Scripts Bash y estructuras de control

Imagínalo así

Un script es como una receta de cocina: una lista de pasos escritos en un archivo que Bash lee y ejecuta en el orden establecido, sin que tengas que teclear cada comando.

Un script Bash es un archivo de texto que contiene instrucciones que serán interpretadas por Bash. Normalmente utiliza la extensión .sh y puede comenzar indicando el intérprete mediante #!/bin/bash. A partir de este punto es posible combinar comandos de Linux con variables, condiciones, ciclos y funciones para automatizar tareas relacionadas con proyectos reales de desarrollo web.

revisar-proyecto.sh
#!/bin/bash echo "Iniciando revisión del proyecto Node.js" pwd ls -la echo "Revisión finalizada"
  • #!/bin/bash se conoce como shebang e indica que el script debe ejecutarse utilizando Bash.
  • echo muestra información en la terminal.
  • pwd y ls -la permiten conocer el directorio actual y visualizar su contenido.

¿Cómo crear y ejecutar un script?

  1. Crear el archivo con un editor de texto:
    $ nano revisar-proyecto.sh
  2. Otorgar permiso de ejecución después de guardar el archivo:
    $ chmod +x revisar-proyecto.sh
  3. Ejecutarlo directamente:
    $ ./revisar-proyecto.sh
  4. O ejecutarlo mediante Bash:
    $ bash revisar-proyecto.sh
La segunda alternativa (bash archivo.sh) resulta especialmente útil cuando el archivo todavía no tiene permiso de ejecución.

Condicionales if

Imagínalo así

Un condicional es una bifurcación en el camino: si la condición se cumple, el script toma un camino; si no, toma otro o simplemente continúa.

La estructura if permite que un script ejecute determinadas instrucciones solamente cuando una condición se cumple. Resulta útil para comprobar si existe un archivo de configuración, si un directorio está disponible, si un comando terminó correctamente o si una herramienta como Node.js está instalada.

sintaxis básica
if [ condición ]; then instrucciones fi

Por ejemplo, un script puede verificar si existe el archivo package.json de un proyecto Node.js. La opción -f comprueba que la ruta corresponde a un archivo existente; para comprobar un directorio se utiliza -d:

verificar-archivo.sh
#!/bin/bash if [ -f /var/www/catalogo-api/package.json ]; then echo "El proyecto Node.js contiene package.json" fi if [ -d /var/www/catalogo-api ]; then echo "El directorio de la API existe" fi

if, else y elif

Cuando el script debe responder de diferentes maneras según el resultado de una condición, se pueden utilizar else y elif.

if / else
#!/bin/bash if [ -f /var/www/catalogo-api/package.json ]; then echo "package.json encontrado" else echo "No se encontró package.json" fi
if / elif / else
#!/bin/bash if [ -d /var/www/catalogo-api ]; then echo "El proyecto existe" elif [ -d /var/www ]; then echo "Existe /var/www, pero no el proyecto" else echo "No existe el entorno esperado" fi

procesos-node.sh
#!/bin/bash procesos=$(pgrep -c node) if [ "$procesos" -gt 0 ]; then echo "Hay procesos Node.js ejecutándose: $procesos" else echo "No hay procesos Node.js activos" fi

La expresión procesos=$(pgrep -c node) ejecuta pgrep y almacena el resultado en la variable procesos. Posteriormente, [ "$procesos" -gt 0 ] comprueba si el número obtenido es superior a cero. Las comillas alrededor de la variable ayudan a evitar problemas cuando está vacía o contiene espacios.

Operadores lógicos

También es posible combinar condiciones. El operador && requiere que ambas condiciones sean verdaderas; || representa una alternativa (basta con que una se cumpla).

operadores lógicos
# Y lógico: ambas condiciones deben cumplirse if [ -f /var/www/catalogo-api/package.json ] && [ -d /var/www/catalogo-api/node_modules ]; then echo "El proyecto tiene package.json y node_modules" else echo "El proyecto no está completamente preparado" fi # O lógico: basta con que se cumpla una if [ -f /etc/nginx/nginx.conf ] || [ -f /etc/nginx/sites-enabled/default ]; then echo "Se encontró configuración de Nginx" fi

Ciclos: for, while y until

Imagínalo así

Un ciclo es como una línea de revisión en una fábrica: el mismo procedimiento se aplica a cada pieza que pasa, hasta que no quedan más o se cumple cierta condición.

Ciclo for

Permite repetir instrucciones para diferentes elementos. Es especialmente útil para recorrer archivos y directorios de un proyecto.

for sobre archivos
#!/bin/bash for archivo in /var/www/catalogo-api/*.js do echo "Archivo JavaScript encontrado: $archivo" done

La combinación de for con if permite realizar operaciones selectivas sobre los elementos encontrados:

for + if
for directorio in /var/www/* do if [ -d "$directorio" ]; then echo "Proyecto encontrado: $directorio" fi done

Ciclo while

Repite instrucciones mientras una condición continúe siendo verdadera.

sintaxis de while
while [ condición ] do instrucciones done
monitorear-node.sh
#!/bin/bash contador=1 while [ "$contador" -le 5 ] do echo "Comprobación número $contador" pgrep -x node contador=$((contador + 1)) sleep 2 done

La variable contador comienza en 1. La condición [ "$contador" -le 5 ] permite ejecutar el ciclo mientras el contador sea menor o igual a cinco. Después, contador=$((contador + 1)) incrementa el valor y sleep 2 espera dos segundos antes de la siguiente comprobación.

Cuidado con el ciclo infinito: una causa frecuente de problemas con while es olvidar modificar la variable utilizada en la condición. Si nunca cambia, el ciclo puede ejecutarse indefinidamente.

Ciclo until

Funciona de forma inversa a while: continúa ejecutándose mientras la condición sea falsa y termina cuando se vuelve verdadera.

preparar-entorno.sh
#!/bin/bash contador=1 until [ "$contador" -gt 3 ] do echo "Preparando entorno: $contador" contador=$((contador + 1)) done

Aquí el ciclo finaliza cuando contador alcanza un valor superior a 3. Aunque while es más frecuente, until resulta útil cuando la lógica se expresa como repetir hasta que ocurra una condición.

CicloSe repite…Úsalo para…
forpara cada elemento de una listarecorrer archivos y directorios
whilemientras la condición sea verdaderarepetir comprobaciones con un contador
untilhasta que la condición sea verdaderaesperar a que ocurra algo

break y continue

Dentro de los ciclos pueden utilizarse break y continue para controlar su ejecución. break termina inmediatamente el ciclo, mientras que continue omite la iteración actual y continúa con el siguiente elemento.

break
for archivo in /var/www/catalogo-api/*.log do if [ -f "$archivo" ]; then echo "Archivo encontrado: $archivo" break # termina el ciclo al encontrar el primero fi done
continue
for archivo in /var/www/catalogo-api/* do if [ -d "$archivo" ]; then continue # omite los directorios fi echo "Archivo: $archivo" done

Funciones Bash

Imagínalo así

Una función es como una herramienta guardada en la caja de herramientas: la construyes una vez, le pones nombre y la usas cada vez que la necesites.

Una función permite agrupar instrucciones relacionadas bajo un nombre que posteriormente puede ejecutarse varias veces. En scripts para desarrollo web permite separar tareas como verificar dependencias, revisar un proyecto, crear respaldos o validar configuraciones.

verificar_node (con la palabra function)
function verificar_node () { if command -v node >/dev/null 2>&1; then echo "Node.js está instalado" else echo "Node.js no está disponible" fi } verificar_node # invocación de la función

También es válida la forma abreviada:

forma abreviada
verificar_node() { if command -v node >/dev/null 2>&1; then echo "Node.js está instalado" else echo "Node.js no está disponible" fi }
command -v node comprueba si el comando node está disponible en el sistema. La función no se ejecuta simplemente por haber sido declarada: es necesario invocarla escribiendo verificar_node.

verificar_proyecto.sh
#!/bin/bash verificar_proyecto() { ruta="$1" if [ -d "$ruta" ]; then echo "Proyecto encontrado: $ruta" if [ -f "$ruta/package.json" ]; then echo "package.json encontrado" else echo "Falta package.json" fi else echo "No existe el directorio: $ruta" return 1 fi } verificar_proyecto "/var/www/catalogo-api"

La función recibe la ruta del proyecto mediante $1. Después comprueba que exista el directorio y busca package.json. return 1 permite indicar que la función terminó con un resultado diferente de éxito.

Construcción de un script completo

Las condiciones, ciclos y funciones pueden combinarse en un mismo script. El siguiente ejemplo revisa diferentes proyectos ubicados en /var/www:

revisar-todos.sh
#!/bin/bash revisar_proyecto() { proyecto="$1" echo "--------------------" echo "Revisando: $proyecto" if [ -f "$proyecto/package.json" ]; then echo "package.json: OK" else echo "package.json: FALTA" fi } for proyecto in /var/www/* do if [ -d "$proyecto" ]; then revisar_proyecto "$proyecto" fi done
  • revisar_proyecto encapsula la revisión de un proyecto.
  • for recorre los elementos existentes dentro de /var/www.
  • if determina cuáles elementos son directorios antes de enviarlos a la función.
Esta estructura representa una forma básica de automatización que puede evolucionar hacia scripts de despliegue, validación y mantenimiento.

Errores frecuentes al escribir scripts

Conocer los errores más comunes te permitirá depurar tus scripts con rapidez. Revisa cada caso y compara la forma incorrecta con la correcta.

1. Olvidar los espacios en las condiciones
comparación
# Incorrecto: if [-f "$archivo"]; then # Correcto: if [ -f "$archivo" ]; then

Los espacios alrededor de [ y ] son necesarios porque Bash interpreta estos elementos como parte de una expresión.

2. Olvidar fi

Todo if debe finalizar con fi. Sin él, Bash no sabe dónde termina el bloque condicional y mostrará un error de sintaxis.

3. Olvidar done

Los ciclos for, while y until deben finalizar con done.

4. No colocar comillas en rutas
comillas
if [ -f "$ruta" ]; then # correcto: las comillas protegen rutas con espacios

Es recomendable utilizar comillas alrededor de las variables que contienen rutas para evitar problemas cuando una ruta contiene espacios.

5. Ejecutar un script sin permisos
permisos
$ ls -l deploy.sh $ chmod +x deploy.sh $ ./deploy.sh

Si se utiliza ./deploy.sh, el archivo debe tener permiso de ejecución. Si no lo tiene, puedes ejecutarlo con bash deploy.sh.

Lista de verificación: espacios en [ ] · cierre con fi / done · comillas en variables · permisos de ejecución · variable del ciclo while que cambia en cada vuelta.

Actividad 1. Validador de un proyecto Node.js

Condicionales if / elif / else

Caso propuesto: construye el script validar-proyecto.sh, que revisa si un proyecto Node.js tiene package.json y node_modules y muestra un mensaje distinto según el caso. Practica en la terminal simulada y luego repite la práctica en tu propio equipo.

Reto 1 de 11

0/11
Guion para realizarla en tu equipo
  1. Crea una carpeta de práctica con un proyecto de ejemplo:
    $ mkdir -p ~/practica-web/catalogo-api $ cd ~/practica-web/catalogo-api $ touch package.json index.js
  2. En ~/practica-web, crea validar-proyecto.sh con nano:
    #!/bin/bash ruta="$HOME/practica-web/catalogo-api" if [ -f "$ruta/package.json" ] && [ -d "$ruta/node_modules" ]; then echo "Proyecto listo: tiene package.json y node_modules" elif [ -f "$ruta/package.json" ]; then echo "Falta node_modules: se debe ejecutar npm install" elif [ -d "$ruta" ]; then echo "El directorio existe, pero falta package.json" else echo "No existe el directorio: $ruta" fi
  3. Asigna permiso con chmod +x validar-proyecto.sh, ejecútalo con ./validar-proyecto.sh y anota el mensaje que aparece.
  4. Prueba los demás casos, ejecutando de nuevo después de cada cambio: crea node_modules con mkdir; elimina package.json con rm; cambia ruta a "$HOME/practica-web/no-existe".
  5. Error intencional: quita los espacios de una condición, por ejemplo if [-f "$ruta/package.json"]; then, ejecuta el script, copia el error y corrígelo.
Producto esperado: el archivo validar-proyecto.sh, capturas de cada ejecución indicando qué parte del condicional (if, elif o else) se ejecutó en cada caso y una explicación breve del error del paso 5.

Actividad 2. Revisión de varios proyectos con ciclos y funciones

Ciclos for + funciones

Caso propuesto: amplía tu carpeta de práctica y crea revisar-proyectos.sh, un script que recorre cada elemento de ~/practica-web, omite los archivos con continue y revisa los directorios mediante la función revisar_proyecto.

Guion para realizarla en tu equipo
  1. Agrega más elementos a la carpeta de práctica:
    $ mkdir -p ~/practica-web/tienda-web ~/practica-web/panel-admin $ touch ~/practica-web/catalogo-api/package.json $ touch ~/practica-web/tienda-web/package.json $ touch ~/practica-web/notas.txt

    #!/bin/bash revisar_proyecto() { proyecto="$1" echo "--------------------" echo "Revisando: $proyecto" if [ -f "$proyecto/package.json" ]; then echo "package.json: OK" else echo "package.json: FALTA" fi } total=0 for elemento in "$HOME"/practica-web/* do if [ -f "$elemento" ]; then echo "Omitiendo archivo: $elemento" continue fi revisar_proyecto "$elemento" total=$((total + 1)) done echo "Proyectos revisados: $total"
