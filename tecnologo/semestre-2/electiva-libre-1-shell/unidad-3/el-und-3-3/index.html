Scripts para respaldos, organización de archivos y diagnóstico

En las unidades anteriores aprendiste a utilizar la terminal para ejecutar comandos de Linux. En esta guía aprenderás a crear scripts de Bash, archivos que permiten automatizar varias tareas con una sola ejecución.

Los scripts son útiles para realizar tareas frecuentes en el desarrollo web, como crear copias de seguridad con tar y rsync, organizar archivos con for, case y find, revisar el estado de un servidor y programar su ejecución periódica con cron. Además, ayudan a reducir errores y ahorrar tiempo, ya que permiten repetir las mismas instrucciones de forma automática. Al finalizar, podrás crear scripts básicos para automatizar tareas comunes en entornos Linux.

¡Automatiza con criterio! Un script bien construido valida sus datos antes de actuar, informa su resultado con un código de salida y se ejecuta solo cuando lo programas.

Estructura de un script, variables y argumentos

Imagínalo así

Un script es como una receta de cocina: una lista de pasos escritos en un archivo que Bash ejecuta de arriba hacia abajo, sin que tengas que teclear cada comando.

Estructura de un script de Bash

Un script de Bash es un archivo de texto plano que contiene una secuencia de comandos que el intérprete bash ejecuta de arriba hacia abajo. Por convención se guarda con extensión .sh y, en un proyecto web, suele ubicarse en una carpeta scripts/ dentro del repositorio (por ejemplo ~/proyectos/tienda-web/scripts/respaldo.sh) para que quede versionado con Git junto al código.

La primera línea de todo script es el shebang, cuyo nombre proviene de los caracteres # (sharp) y ! (bang). Indica al sistema qué intérprete debe ejecutar el archivo:

encabezado de un script
#!/usr/bin/env bash set -euo pipefail
#!/usr/bin/env bash

Busca bash en el PATH del usuario; es más portátil que escribir #!/bin/bash de forma fija.

set -e

Detiene el script en cuanto un comando falla, en lugar de continuar con un estado inconsistente.

set -u

Produce un error si se usa una variable que no fue definida.

set -o pipefail

Hace que una tubería se considere fallida si cualquiera de sus comandos falla, no solo el último.

¿Cómo ejecutar un script?

Existen dos formas de ejecutarlo:

  1. A través del intérprete:
    $ bash scripts/respaldo.sh
  2. Con permiso de ejecución (una sola vez) y llamándolo directamente:
    $ chmod +x scripts/respaldo.sh $ ./scripts/respaldo.sh
El ./ es obligatorio porque el directorio actual no forma parte del PATH.
Errores comunes
  • Guardar el archivo con finales de línea de Windows (CRLF) desde VS Code produce el error /usr/bin/env: 'bash\r': No such file or directory; se corrige seleccionando LF en la barra inferior del editor.
  • Permission denied indica que falta el chmod +x.

Variables y sustitución de comandos

Una variable en Bash se declara con NOMBRE=valor, sin espacios alrededor del signo igual, y se lee anteponiendo $. Por convención, las variables de configuración de un script se escriben en mayúsculas.

variables de configuración
PROYECTO="$HOME/proyectos/tienda-web" DESTINO="$HOME/respaldos" FECHA=$(date +%Y-%m-%d_%H%M) ARCHIVO="$DESTINO/tienda-web_$FECHA.tar.gz" echo "Se generará: $ARCHIVO"

La sintaxis $(comando) se denomina sustitución de comandos: ejecuta el comando y reemplaza la expresión por su salida. En el ejemplo, date +%Y-%m-%d_%H%M devuelve un texto como 2026-09-30_1415, que se usa para que cada respaldo tenga un nombre único y ordenable alfabéticamente. Los formatos de date más usados en nombres de archivo son:

Haz clic en cada fila para resaltarla:

FormatoSalida de ejemploUso típico

+%Y-%m-%d_%H%M2026-09-30_1415Varios respaldos en un mismo día
+%Y-%m2026-09Carpetas mensuales de logs o recursos

Argumentos del script

Los argumentos que recibe el script desde la línea de comandos se leen con $1, $2, etc.; $# contiene la cantidad de argumentos y $0 el nombre del script. La expresión ${1:-valor} asigna un valor por defecto cuando el argumento no se envía:

argumento con valor por defecto
PROYECTO="${1:-$HOME/proyectos/tienda-web}"

Con esta línea, ./respaldo.sh ~/proyectos/blog-astro respalda el blog, mientras que ./respaldo.sh sin argumentos respalda la tienda.

Errores comunes
  • Escribir FECHA = $(date +%F) con espacios hace que Bash interprete FECHA como un comando.
  • Usar una variable sin comillas (cd $PROYECTO) falla si la ruta contiene espacios, como ~/Proyectos UNI/tienda-web; por eso las variables con rutas se escriben siempre entre comillas dobles: cd "$PROYECTO".

Condicionales y códigos de salida

Imagínalo así

El código de salida es como el semáforo con el que cada comando avisa cómo le fue: 0 es luz verde (éxito) y cualquier otro número es una alerta de error.

Todo comando en Linux termina con un código de salida (exit status): 0 significa éxito y cualquier otro valor indica un error. El código del último comando ejecutado queda en la variable especial $?. Los condicionales if de Bash se basan precisamente en estos códigos.

Para evaluar condiciones sobre archivos y textos se usa [[ ... ]], con espacios obligatorios después de [[ y antes de ]]. Las pruebas más utilizadas en scripts de administración son:

Haz clic en cada fila para resaltarla:

PruebaEs verdadera cuando…
-d rutala ruta existe y es un directorio
-f rutala ruta existe y es un archivo regular
-e rutala ruta existe (de cualquier tipo)
-z "$VAR"la variable está vacía
"$A" == "$B"los textos son iguales
$N -gt 80el número es mayor que 80 (-lt, -ge, -le, -eq)

El siguiente fragmento valida la entrada antes de hacer cualquier operación, una práctica indispensable en scripts que crean o borran archivos:

validación de entrada
if [[ ! -d "$PROYECTO" ]]; then echo "Error: no existe el directorio $PROYECTO" >&2 exit 1 fi if [[ ! -f "$PROYECTO/package.json" ]]; then echo "Aviso: $PROYECTO no parece un proyecto Node.js" >&2 fi mkdir -p "$DESTINO"

Anatomía de una validación

Haz clic en cada parte de if [[ ! -d "$PROYECTO" ]]; then exit 1 fi para conocer su función:

La primera condición usa ! para negar la prueba: si el directorio no existe, se imprime un mensaje y el script termina con exit 1, lo que permite que otro programa (o cron) sepa que la ejecución falló. La redirección >&2 envía el mensaje a la salida de errores en lugar de la salida estándar, de modo que los errores se distinguen en los logs. La segunda condición solo advierte, sin detener la ejecución. Finalmente, mkdir -p crea la carpeta de destino si no existe y no genera error si ya existe.

Un comando como condición

Un comando también puede usarse directamente como condición. Por ejemplo, if command -v docker > /dev/null; then ... verifica si Docker está instalado antes de intentar usarlo; /dev/null es un archivo especial que descarta todo lo que se le envía.

verificar Docker y leer $?
if command -v docker > /dev/null; then echo "Docker está instalado" fi $ ./scripts/respaldo.sh ~/proyectos/no-existe $ echo $? 1

Respaldos con tar, rsync y find

Imagínalo así

tar es como empacar tu proyecto en una caja sellada; rsync es como mantener una copia gemela que solo se actualiza con lo que cambió; y find es el encargado de bodega que retira las cajas viejas.

Respaldos comprimidos con tar

El comando tar (de tape archive, porque originalmente se usaba para escribir en cintas magnéticas) agrupa muchos archivos y carpetas en un solo archivo, conservando la estructura de directorios y los permisos. Combinado con compresión gzip produce los conocidos archivos .tar.gz, el formato estándar para respaldar proyectos y configuraciones en servidores Linux.

La sintaxis general es tar [opciones] archivo.tar.gz rutas.... Las opciones se combinan en un solo bloque de letras:

OpciónSignificadoCuándo usarla
-ccreate: crea un archivo nuevoAl generar el respaldo
-xextract: extrae el contenidoAl restaurar un respaldo
-tlist: lista el contenido sin extraerPara verificar un respaldo antes de restaurarlo
-zcomprime o descomprime con gzipSiempre que el archivo termine en .tar.gz
-findica el nombre del archivo; debe ir al final del bloqueSiempre
-vverbose: muestra cada archivo procesadoEn pruebas manuales; se omite en scripts automáticos
-C dircambia al directorio indicado antes de operarPara evitar rutas absolutas dentro del respaldo
--exclude=patrónomite archivos o carpetas que coincidanPara excluir node_modules, dist, .git, *.log

Los tres usos fundamentales son crear, listar y restaurar:

crear, listar y restaurar
$ tar -czf ~/respaldos/nginx_2026-09-30.tar.gz -C /etc nginx $ tar -tzf ~/respaldos/nginx_2026-09-30.tar.gz | head $ tar -xzf ~/respaldos/tienda-web_2026-09-30_1415.tar.gz -C ~/restauracion

La primera línea respalda la configuración de Nginx: -C /etc hace que el archivo contenga la ruta relativa nginx/sites-available/... en lugar de /etc/nginx/.... La segunda lista las primeras entradas del respaldo para comprobar que no está vacío. La tercera restaura un proyecto dentro de ~/restauracion, sin tocar la copia de trabajo original.

Errores comunes con tar
  • Escribir -cfz en lugar de -czf. Como -f toma el siguiente texto como nombre de archivo, tar -cfz respaldo.tar.gz ... crea un archivo llamado z. La regla es que f sea siempre la última letra del bloque.
  • Incluir node_modules/. En un proyecto Node.js esta carpeta puede pesar más de 300 MB y se regenera con npm install a partir de package.json y package-lock.json. Lo mismo ocurre con dist/ o build/, que se regeneran con npm run build.
  • Respaldar con rutas absolutas. Sin -C, al extraer el respaldo se recrea la ruta completa dentro del destino.
  • Respaldar el archivo .env sin control. Contiene credenciales de base de datos y llaves de API; si el respaldo se comparte o se sube a un repositorio, esas credenciales quedan expuestas. Se debe decidir de forma explícita si se incluye y proteger el respaldo con permisos 600.

Sincronización con rsync

rsync (remote sync) copia archivos entre dos ubicaciones transfiriendo únicamente lo que cambió desde la última sincronización. A diferencia de tar, no genera un archivo comprimido sino una réplica navegable del directorio, lo que lo hace adecuado para mantener un espejo actualizado del proyecto en un disco externo o para desplegar una carpeta dist/ a un servidor remoto por SSH.

espejo del proyecto
$ rsync -av --delete --exclude='node_modules/' --exclude='.git/' \ ~/proyectos/tienda-web/ /media/estudiante/USB/espejo-tienda-web/
OpciónFunción
-amodo archivo: copia recursivamente y conserva permisos, fechas y enlaces simbólicos
-vmuestra los archivos transferidos
-n o --dry-runsimula la operación sin copiar ni borrar nada
--deleteelimina del destino los archivos que ya no existen en el origen
--excludeomite rutas que coincidan con el patrón
-zcomprime durante la transferencia (útil por red)
Cuidado con la barra final del origen: rsync -a ~/proyectos/tienda-web/ destino/ copia el contenido de la carpeta dentro de destino/, mientras que rsync -a ~/proyectos/tienda-web destino/ copia la carpeta completa y crea destino/tienda-web/. Combinado con --delete, un origen o destino mal escrito puede borrar archivos que no se deseaba eliminar. Por eso, toda orden con --delete se prueba primero con --dry-run y se revisa la salida antes de ejecutarla de verdad.

Rotación de respaldos con find

Un script de respaldo que se ejecuta todos los días llena el disco en pocas semanas si no elimina las copias antiguas. Este proceso se conoce como rotación y se implementa con find, comando que recorre un directorio de forma recursiva y selecciona archivos según criterios como nombre, tipo, tamaño o fecha de modificación, para luego listarlos o actuar sobre ellos.

rotación: primero listar, luego borrar
$ find ~/respaldos -maxdepth 1 -type f -name 'tienda-web_*.tar.gz' -mtime +7 -print $ find ~/respaldos -maxdepth 1 -type f -name 'tienda-web_*.tar.gz' -mtime +7 -delete
-maxdepth 1

Limita la búsqueda a la carpeta indicada, sin entrar en subcarpetas.

-type f

Selecciona solo archivos regulares (d sería directorios).

-name 'patrón'

Filtra por patrón; las comillas simples evitan que la terminal expanda el * antes de que find lo reciba.

-mtime +7

Selecciona archivos modificados hace más de 7 días completos (-mtime -1 sería menos de un día).

-print

Lista los resultados.

-delete

Elimina los resultados.

Error común: find evalúa sus expresiones de izquierda a derecha, por lo que find ~/respaldos -delete -name '*.tar.gz' borra todo el contenido de la carpeta antes de filtrar por nombre. La acción -delete va siempre al final, y la orden se ejecuta primero con -print para confirmar qué archivos se verían afectados.

Script completo de respaldo

El siguiente script integra los apartados anteriores. Recibe opcionalmente la ruta del proyecto, genera un respaldo fechado sin dependencias ni compilaciones, lo verifica y conserva solo los últimos 7 días:

respaldo.sh
#!/usr/bin/env bash set -euo pipefail PROYECTO="${1:-$HOME/proyectos/tienda-web}" DESTINO="$HOME/respaldos" DIAS_RETENCION=7 NOMBRE=$(basename "$PROYECTO") FECHA=$(date +%Y-%m-%d_%H%M) ARCHIVO="$DESTINO/${NOMBRE}_${FECHA}.tar.gz" if [[ ! -d "$PROYECTO" ]]; then echo "[ERROR] No existe $PROYECTO" >&2 exit 1 fi mkdir -p "$DESTINO" tar -czf "$ARCHIVO" \ --exclude='node_modules' --exclude='dist' --exclude='.git' --exclude='*.log' \ -C "$(dirname "$PROYECTO")" "$NOMBRE" if tar -tzf "$ARCHIVO" > /dev/null; then echo "[OK] $(date '+%F %T') Respaldo creado: $ARCHIVO ($(du -h "$ARCHIVO" | cut -f1))" else echo "[ERROR] El archivo $ARCHIVO está dañado" >&2 exit 2 fi find "$DESTINO" -maxdepth 1 -type f -name "${NOMBRE}_*.tar.gz" -mtime +"$DIAS_RETENCION" -delete
  1. Configuración. Las primeras variables concentran lo que puede cambiar: si se necesita otro destino o más días de retención, solo se modifica ese bloque. basename extrae el último componente de la ruta (tienda-web) y dirname la carpeta que lo contiene (/home/estudiante/proyectos); ambos se usan para que tar -C guarde rutas relativas.
  2. Validación. El primer if impide continuar si el proyecto no existe y mkdir -p crea la carpeta de destino.
  3. Creación. El comando tar está dividido en tres líneas mediante \, que indica a Bash que la orden continúa en la siguiente línea; no debe haber ningún espacio después de esa barra.
  4. Verificación. tar -tzf lee el archivo completo: si está corrupto devuelve un código distinto de cero y el script informa el error con exit 2. Si todo es correcto, se imprime una línea con fecha, hora, ruta y tamaño, apta para acumularse en un log.
  5. Rotación. La última línea elimina solo los respaldos de este mismo proyecto, gracias al patrón ${NOMBRE}_*.tar.gz.

Organización de archivos con for, case y find

Imagínalo así

Un script clasificador es como un cartero que reparte la correspondencia: toma cada sobre (for), lee la dirección (case) y lo deja en el buzón correcto.

Recorrer archivos con bucles for

El bucle for ejecuta un bloque de comandos una vez por cada elemento de una lista. En scripts de organización, esa lista suele construirse con un patrón de nombres (glob), que la terminal expande a los archivos que coinciden:

for sobre archivos .png
for imagen in ~/proyectos/landing-cafe/public/img/*.png; do echo "Procesando $imagen" done

La variable imagen toma en cada vuelta la ruta de un archivo .png distinto. El bloque se delimita con do y done.

Errores comunes
  • Si la carpeta no contiene ningún .png, Bash no expande el patrón y el bucle se ejecuta una vez con el texto literal *.png. Se evita activando al inicio del script shopt -s nullglob, que hace que un patrón sin coincidencias produzca una lista vacía.
  • Es un error recorrer la salida de ls (for f in $(ls)), porque los nombres con espacios, como logo cafe final.png, se parten en varias palabras.

Extraer nombre y extensión

Para clasificar un archivo es necesario conocer su extensión. Bash permite obtenerla sin comandos externos mediante la expansión de parámetros, que recorta texto de una variable según un patrón. Con archivo="hero-banner.WEBP":

ExpresiónResultadoDescripción
${archivo##*.}WEBPelimina todo hasta el último punto: la extensión
${archivo%.*}hero-bannerelimina desde el último punto: el nombre sin extensión
${archivo,,}hero-banner.webpconvierte a minúsculas
La conversión a minúsculas es importante porque Linux distingue mayúsculas: foto.JPG y foto.jpg son archivos distintos, y un patrón que solo contemple jpg ignoraría el primero.

Clasificar con case

La estructura case compara un valor contra varios patrones y ejecuta el bloque del primero que coincida. Es más legible que encadenar varios if cuando se evalúan muchas alternativas, como las extensiones de un proyecto web. Cada patrón termina en ), varios patrones se separan con |, cada bloque cierra con ;; y *) actúa como caso por defecto.

El siguiente script ordena los recursos que entrega un diseñador en una sola carpeta y los ubica en la estructura public/ de un proyecto:

organizar.sh
#!/usr/bin/env bash set -euo pipefail shopt -s nullglob ORIGEN="${1:-$HOME/Descargas/recursos-landing}" DESTINO="$HOME/proyectos/landing-cafe/public" for archivo in "$ORIGEN"/*; do [[ -f "$archivo" ]] || continue nombre=$(basename "$archivo") extension="${nombre##*.}" extension="${extension,,}" case "$extension" in png|jpg|jpeg|webp|svg|gif) carpeta="img" ;; woff|woff2|ttf|otf) carpeta="fonts" ;; css) carpeta="css" ;; js|mjs) carpeta="js" ;; mp4|webm) carpeta="video" ;; *) carpeta="otros" ;; esac mkdir -p "$DESTINO/$carpeta" mv -n "$archivo" "$DESTINO/$carpeta/" echo "$nombre -> public/$carpeta/" done

La línea [[ -f "$archivo" ]] || continue usa el operador || («o» lógico): si el elemento no es un archivo regular, por ejemplo una subcarpeta, continue salta a la siguiente vuelta del bucle. Luego se obtiene el nombre, se extrae la extensión y se pasa a minúsculas. El bloque case asigna la carpeta de destino, y cualquier extensión no prevista termina en otros/ para revisión manual. Finalmente, mkdir -p garantiza que la carpeta exista y mv -n (no clobber) mueve el archivo sin sobrescribir uno que ya exista con el mismo nombre en el destino; en ese caso el archivo permanece en el origen, lo que evita pérdidas de información.

Organizar por fecha

Otra forma habitual de organización es agrupar archivos por mes, por ejemplo, los logs de una aplicación o las capturas de pantalla de pruebas. El comando date -r archivo +%Y-%m devuelve el año y mes de la última modificación de ese archivo, valor que puede usarse como nombre de carpeta:

carpeta por mes
mes=$(date -r "$archivo" +%Y-%m) mkdir -p "$HOME/proyectos/api-pedidos/logs/archivo/$mes" mv -n "$archivo" "$HOME/proyectos/api-pedidos/logs/archivo/$mes/"

Actuar sobre los resultados de find

Cuando los archivos están repartidos en subcarpetas, find es más adecuado que un for con patrones. La acción -exec ejecuta un comando sobre cada resultado; {} representa el archivo encontrado y \; marca el final del comando:

find con -exec y -prune
$ find ~/proyectos/api-pedidos/logs -type f -name '*.log' -mtime +3 -exec gzip {} \; $ find ~/proyectos -type d -name node_modules -prune -o -type f -size +5M -print

La primera orden comprime con gzip los logs con más de 3 días, que pasan a llamarse app.log.gz y ocupan una fracción del espacio original. La segunda localiza archivos de más de 5 MB en todos los proyectos, útiles de detectar antes de un git push; la combinación -name node_modules -prune -o le indica a find que no entre en las carpetas node_modules, que de otro modo llenarían el resultado.

-type-type dpor tipo: f archivo, d directorio
-size-size +5Mpor tamaño (k, M, G)
-mtime-mtime -1por días desde la última modificación

Diagnóstico del sistema y análisis de logs

Imagínalo así

Diagnosticar un servidor es como una consulta médica: primero se toman los signos vitales (carga, disco, memoria), luego se revisa si el órgano clave (el proceso) funciona y, por último, se lee el historial clínico (los logs).

Comandos de diagnóstico del sistema

Cuando un sitio deja de responder, el diagnóstico sigue un orden: primero se revisa si la máquina tiene recursos disponibles (carga, disco, memoria), después si el proceso de la aplicación está en ejecución y escuchando en su puerto, y por último qué dicen los logs. Cada uno de los siguientes comandos responde una de esas preguntas.

ComandoPregunta que respondeQué observar
uptime¿Cuánto lleva encendido el equipo y qué tan cargado está?Los tres valores de load average (1, 5 y 15 min); si superan el número de núcleos (nproc), hay saturación
df -h¿Queda espacio en las particiones?La columna Use%; por encima de 90 % en / pueden fallar npm install, Docker y la escritura de logs
du -sh ruta/*¿Qué carpetas ocupan más espacio?Se ordena con sort -h para ver las más pesadas al final
free -h¿Cuánta memoria RAM queda?La columna available, no free: Linux usa la RAM libre como caché y la libera cuando se necesita
ps aux --sort=-%mem¿Qué procesos consumen más memoria?Se combina con head -n 6 para ver los cinco primeros
ss -tulpn¿Qué puertos están abiertos y qué proceso los usa?Si el puerto 3000 (Node.js) o 80 (Nginx) aparece en estado LISTEN
tail -n 50 archivo / tail -f archivo¿Qué se registró recientemente?-f (follow) muestra en vivo las líneas nuevas; se sale con Ctrl+C
journalctl -u nginx --since "1 hour ago"¿Qué registró un servicio de systemd?Mensajes de error al arrancar o reiniciar el servicio

Todos los comandos de tamaño aceptan -h (human-readable), que muestra las cantidades en K, M o G en lugar de bloques o bytes. En el caso de ss, las letras significan: t TCP, u UDP, l solo puertos en escucha, p proceso propietario y n números en lugar de nombres de servicio; la columna del proceso requiere sudo para mostrar procesos de otros usuarios.

Caso típico: al ejecutar npm run dev aparece el error EADDRINUSE: address already in use :::3000. La orden ss -tlpn | grep ':3000' muestra qué proceso ocupa el puerto y su PID, con lo cual se decide si cerrarlo o usar otro puerto.

Análisis de logs con tuberías

Los logs de acceso de Nginx (/var/log/nginx/access.log) registran una línea por petición con un formato fijo, llamado combined:

una línea de access.log
190.24.81.17 - - [30/Sep/2026:10:15:32 -0500] "GET /api/productos HTTP/1.1" 200 1532 "-" "Mozilla/5.0"

Si se separa la línea por espacios, el campo 1 es la IP del cliente, el 7 la ruta solicitada y el 9 el código de estado HTTP. awk es una herramienta que procesa texto por columnas: $1 representa el primer campo de cada línea, $9 el noveno, y una condición antes de las llaves filtra las líneas. Encadenado con sort, uniq y head mediante tuberías (|), permite responder preguntas concretas:

preguntas sobre el log
LOG=/var/log/nginx/access.log # Las cinco IP con más peticiones awk '{print $1}' "$LOG" | sort | uniq -c | sort -rn | head -n 5 # Rutas que devolvieron 404 awk '$9 == 404 {print $7}' "$LOG" | sort | uniq -c | sort -rn # Cantidad de errores del servidor (500 a 599) grep -c '" 5[0-9][0-9] ' "$LOG"
  1. Top de IP: awk imprime solo la IP, sort agrupa las iguales, uniq -c las cuenta, sort -rn ordena numéricamente de mayor a menor y head conserva las cinco primeras.
  2. Rutas con 404: lista los recursos que no existen, útil para detectar enlaces rotos o recursos faltantes tras un despliegue.
  3. Errores 5xx: cuenta con grep -c las respuestas de error del servidor (códigos 500 a 599).
Error común: uniq solo agrupa líneas iguales consecutivas; si se omite el primer sort, el conteo sale fragmentado e incorrecto.

Script de diagnóstico con umbral de alerta

El siguiente script reúne los comandos anteriores en un reporte fechado y emite una alerta cuando el disco supera un umbral:

diagnostico.sh
#!/usr/bin/env bash set -uo pipefail UMBRAL_DISCO=80 REPORTE="$HOME/diagnosticos/diagnostico_$(date +%F_%H%M).txt" mkdir -p "$(dirname "$REPORTE")" { echo "=== Diagnóstico de $(hostname) - $(date '+%F %T') ===" echo; echo "--- Carga ---"; uptime echo; echo "--- Disco ---"; df -h / echo; echo "--- Memoria ---"; free -h echo; echo "--- Top 5 procesos por memoria ---" ps aux --sort=-%mem | head -n 6 echo; echo "--- Puertos en escucha ---"; ss -tln } | tee "$REPORTE" USO=$(df --output=pcent / | tail -n 1 | tr -dc '0-9') if (( USO > UMBRAL_DISCO )); then echo "[ALERTA] La partición / está al ${USO}%" | tee -a "$REPORTE" exit 1 fi

En este script se usa set -uo pipefail sin -e, porque un diagnóstico debe seguir recopilando información aunque un comando individual falle. Las llaves { ... } agrupan todas las salidas para redirigirlas juntas; tee las muestra en pantalla y al mismo tiempo las guarda en el archivo del reporte (tee -a agrega al final en lugar de sobrescribir). Para obtener el porcentaje de disco como número, df --output=pcent / imprime solo la columna de uso, tail -n 1 descarta el encabezado y tr -dc '0-9' elimina todo lo que no sea dígito (el espacio y el símbolo %). Los dobles paréntesis (( ... )) evalúan expresiones aritméticas, donde se pueden usar > y < directamente.

Programar scripts con cron

Imagínalo así

cron es como un despertador con muchas alarmas: cada línea de la tabla define cuándo suena y qué script debe ejecutarse en ese momento.

cron (del griego chronos, tiempo) es el servicio de Linux que ejecuta comandos de forma periódica. Cada usuario tiene su propia tabla de tareas, que se edita con crontab -e y se consulta con crontab -l. Cada línea define cinco campos de tiempo seguidos del comando:

crontab -e
# min hora día-mes mes día-semana comando 30 2 * * * /home/estudiante/proyectos/tienda-web/scripts/respaldo.sh >> /home/estudiante/respaldos/respaldo.log 2>&1 0 */6 * * * /home/estudiante/scripts/diagnostico.sh > /dev/null 2>&1 0 8 * * 1-5 /home/estudiante/scripts/organizar-recursos.sh

La primera tarea ejecuta el respaldo todos los días a las 2:30 a. m.; la segunda, el diagnóstico cada seis horas; la tercera, la organización de recursos a las 8:00 de lunes a viernes. El asterisco significa «cualquier valor», */6 «cada 6» y 1-5 un rango (0 y 7 representan el domingo). El sitio crontab.guru traduce una expresión a lenguaje natural y es útil para verificarla.

Anatomía de una línea de crontab

Haz clic en cada parte de la primera tarea para conocer su función:

30minuto
2hora
*día del mes
*mes
*día de la semana
/home/…/respaldo.shcomando
>> respaldo.log 2>&1salida a un log
Errores comunes
  • Usar rutas relativas o ~. cron no se ejecuta desde la carpeta personal ni carga la misma configuración de la terminal; las rutas deben ser absolutas, tanto la del script como las que usa internamente (por eso los scripts de esta guía usan $HOME).
  • Asumir el mismo PATH. Herramientas instaladas con nvm, como node o npm, pueden no encontrarse; se invocan con su ruta completa, obtenida con which node.
  • No guardar la salida. Sin >> archivo.log 2>&1, los mensajes y errores se pierden. >> agrega al log y 2>&1 redirige la salida de errores (descriptor 2) al mismo destino que la salida estándar (descriptor 1).
  • Olvidar el permiso de ejecución. El script debe tener chmod +x, o la línea debe invocarlo como bash /ruta/al/script.sh.
Lista de verificación: shebang y set -euo pipefail · variables entre comillas · validar entradas con [[ ]] y exit · probar find con -print y rsync con --dry-run · rutas absolutas y log en cron.

Actividad 1. Respaldo automatizado

tar + exit + cron

Caso propuesto: crea un script de respaldo con tar que excluya carpetas innecesarias, verifica y restaura el respaldo, comprueba el código de salida ante un error y programa su ejecución diaria con cron. Practica en la terminal simulada y luego repite el proceso en tu propio equipo.

Reto 1 de 15

estudiante@linux:~
estudiante@linux:~$
0/15
Guion para realizarla en tu equipo
  1. Crea un proyecto de práctica con algunos archivos de ejemplo:
    $ mkdir -p ~/proyectos/tienda-web/{src,node_modules,dist,scripts} $ cd ~/proyectos/tienda-web $ touch package.json src/index.js node_modules/libreria.js dist/app.js error.log
  2. Crea el archivo scripts/respaldo.sh con el siguiente contenido:
    #!/usr/bin/env bash set -euo pipefail PROYECTO="${1:-$HOME/proyectos/tienda-web}" DESTINO="$HOME/respaldos" NOMBRE=$(basename "$PROYECTO") FECHA=$(date +%Y-%m-%d_%H%M) ARCHIVO="$DESTINO/${NOMBRE}_${FECHA}.tar.gz" if [[ ! -d "$PROYECTO" ]]; then echo "[ERROR] No existe $PROYECTO" >&2 exit 1 fi mkdir -p "$DESTINO" tar -czf "$ARCHIVO" --exclude='node_modules' --exclude='dist' \ --exclude='*.log' -C "$(dirname "$PROYECTO")" "$NOMBRE" echo "[OK] Respaldo creado: $ARCHIVO"
  3. Asigna permiso de ejecución con chmod +x scripts/respaldo.sh y ejecútalo con ./scripts/respaldo.sh. Anota el nombre del respaldo que muestra el script.
  4. Verifica el contenido del respaldo sin extraerlo, reemplazando el nombre por el que obtuviste:
    $ tar -tzf ~/respaldos/tienda-web_AAAA-MM-DD_HHMM.tar.gz
    Comprueba que no aparezcan node_modules, dist ni error.log.
  5. Restaura el respaldo en una carpeta aparte y revisa su contenido:
    $ mkdir -p ~/restauracion $ tar -xzf ~/respaldos/tienda-web_AAAA-MM-DD_HHMM.tar.gz -C ~/restauracion $ ls -R ~/restauracion
  6. Ejecuta el script con una ruta que no existe, ./scripts/respaldo.sh ~/proyectos/no-existe, y luego consulta el código de salida con echo $?.
  7. Programa el respaldo con crontab -e para que se ejecute todos los días a las 2:30 a. m. Usa rutas absolutas (consulta tu ruta personal con echo $HOME):
    30 2 * * * /home/TU_USUARIO/proyectos/tienda-web/scripts/respaldo.sh >> /home/TU_USUARIO/respaldos/respaldo.log 2>&1
    Para comprobar que funciona, puedes usar temporalmente */2 * * * * (cada 2 minutos), revisar el log con tail ~/respaldos/respaldo.log y luego dejar de nuevo la programación diaria. Confirma la tarea con crontab -l.
