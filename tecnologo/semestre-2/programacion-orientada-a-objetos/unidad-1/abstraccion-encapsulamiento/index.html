Abstracción y encapsulamiento 🔐

La abstracción y el encapsulamiento son principios fundamentales de la programación orientada a objetos. Permiten representar únicamente los elementos importantes de un problema y proteger la información de los objetos para desarrollar software más organizado, seguro y fácil de mantener.

✨ Modela lo esencial, protege los datos y construye objetos en los que puedas confiar. 🚀

Objetivos de aprendizaje 🎯

  • 🧠Comprender el concepto de abstracción y su aplicación en el modelado de clases.
  • 🔎Diferenciar la abstracción del encapsulamiento.

📘 Primero: comprende las ideas

Base conceptual: modelar y proteger

Antes de programar, necesitamos tomar dos decisiones: qué representa nuestro objeto y cómo cuidará su información. La abstracción responde la primera; el encapsulamiento, la segunda.

🎯

Abstracción: quedarse con lo esencial

Abstraer es construir una representación simplificada de algo. No significa borrar información al azar, sino elegir la que importa para el problema que queremos resolver.

Pregunta clave

“¿Qué datos y acciones necesita este objeto para cumplir su propósito?”

Ejemplo: para una tienda, un producto puede necesitar nombre, precio, stock y la acción vender. El peso del computador donde se ejecuta el sistema no es relevante para ese modelo.

🔐

Encapsulamiento: controlar el acceso

Encapsular es reunir el estado y las operaciones relacionadas dentro de un objeto, ocultando los detalles internos que no deberían manipularse directamente.

Pregunta clave

“¿Qué debe permanecer protegido y mediante qué operación se puede cambiar?”

Ejemplo: el precio se guarda de forma privada y se cambia con actualizarPrecio(), método que rechaza valores negativos.

Abstracción y encapsulamiento no son lo mismo 🔎

📦

Estado

Son los datos que describen al objeto en un momento: nombre, precio y cantidad disponible.

⚙️

Comportamiento

Son las acciones que sabe realizar: vender, reponer, consultar o actualizar.

🤝

Interfaz pública

Es el conjunto de operaciones que otros objetos pueden usar sin conocer la implementación interna.

Cómo trabajan juntas 🧠

1. Analiza

Identifica el problema.

2. Abstrae

Elige datos y acciones relevantes.

3. Encapsula

Protege el estado y define entradas.

4. Valida

Impide estados incorrectos.

Ejemplo completo: una cuenta digital 💳

  • Propósito: guardar dinero y permitir movimientos controlados.
  • Abstracción: saldo, titular, depositar y retirar.
  • Estado privado: el saldo no se modifica directamente.
  • Interfaz pública: depositar(valor) y retirar(valor).
  • Reglas: valor positivo y retiro no mayor al saldo disponible.

¿Qué se gana con este diseño? 🌟

  • ✅ Reduce cambios accidentales en los datos.
  • ✅ Mantiene las reglas en un solo lugar.
  • ✅ Permite modificar detalles internos sin romper otros módulos.
  • ✅ Facilita probar cada comportamiento.
  • ✅ Hace que la clase sea más clara para otros programadores.

Errores comunes y cómo corregirlos 🧯

❌ Todo público: cualquiera cambia precio o stock.

✅ Mejor: datos privados y operaciones con reglas.

❌ Getter y setter para todo: solo disfraza el acceso directo.

✅ Mejor: métodos con intención, como vender().

❌ Clase gigante: representa demasiadas responsabilidades.

✅ Mejor: abstraer por propósito y separar conceptos.

❌ Validar fuera: cada pantalla aplica reglas distintas.

✅ Mejor: el propio objeto conserva sus invariantes.

Encapsulamiento paso a paso en Java 💻

En Java protegemos el estado y ofrecemos métodos públicos con validaciones.

Estado privado
private double precio;
Cambio controlado
public void actualizarPrecio(double valor) {
  if (!Double.isFinite(valor) || valor <= 0) {
    throw new IllegalArgumentException("Precio inválido");
  }
  precio = valor;
}
Consulta pública
public double consultarPrecio() {
  return precio;
}

En Java, private restringe el acceso al estado; los métodos públicos definen cómo utilizarlo.

Una puerta no deja que cualquiera mueva el pestillo interno: ofrece manija y cerradura. Una clase hace algo parecido al ocultar su estado y exponer operaciones que aplican reglas. Así, cambiar la representación interna no obliga a quienes usan la clase a reescribir su código.

Los métodos públicos forman el “contrato” del objeto. El simulador representa el comportamiento del ejemplo Java: valida el precio antes de cambiar el campo privado.

class Producto {
  private final String nombre;
  private double precio;
  public Producto(String nombre, double precio) {
    this.nombre = nombre;
    actualizarPrecio(precio);
  }
  public void actualizarPrecio(double valor) {
    if (!Double.isFinite(valor) || valor <= 0) {
      throw new IllegalArgumentException("El precio debe ser mayor que 0");
    }
    this.precio = valor;
  }
  public double consultarPrecio() { return precio; }
}

Una invariante es una regla que siempre debe cumplirse mientras el objeto sea válido: un stock no puede ser negativo, un descuento debe estar entre 0 y 100, y una cuenta no debería retirar más de lo permitido.

🐞 Caza el bug: una venta de 8 unidades llega cuando solo hay 5

public void vender(int cantidad) {
  this.stock -= cantidad; // Falta validar la cantidad
}

En una API, copiar automáticamente todos los campos enviados por un usuario puede permitir cambios sensibles. OWASP denomina este riesgo Broken Object Property Level Authorization. La defensa se parece al encapsulamiento: aceptar únicamente las propiedades autorizadas y usar operaciones específicas.

❌ Copia indiscriminada

// Ejemplo inseguro: acepta un rol enviado por el cliente.
usuario.setRol(body.get("rol"));

Podría aceptar rol: "admin".

✅ Lista permitida

usuario.cambiarPerfil(
  body.get("nombre"), body.get("ciudad")
);

Solo modifica campos previstos.
