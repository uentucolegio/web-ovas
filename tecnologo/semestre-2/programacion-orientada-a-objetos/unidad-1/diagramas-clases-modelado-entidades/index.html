Diagramas de clases y modelado de entidades 🗺️

Los diagramas de clases son una herramienta fundamental del lenguaje UML que permite representar la estructura de un sistema orientado a objetos. Facilitan la identificación de clases, atributos, métodos y relaciones antes de iniciar la implementación del software.

✨ Convierte una situación real en un mapa que todo el equipo pueda comprender. 🚀

Objetivos de aprendizaje 🎯

  • 🧠Comprender la utilidad de los diagramas de clases en el diseño de software.
  • 🔍Identificar entidades, atributos, métodos y relaciones dentro de un problema.
  • ✏️Modelar diagramas de clases sencillos utilizando los elementos básicos de UML.
📘 Primero: aprende a leer el mapa

UML: un lenguaje visual compartido

UML significa Lenguaje Unificado de Modelado. No ejecuta el sistema ni reemplaza el código: ofrece símbolos acordados para pensar, conversar y documentar decisiones de diseño. La especificación vigente 2.5.1 fue publicada por OMG en diciembre de 2017.

📸 Una fotografía estructural

El diagrama muestra qué tipos existen, qué información manejan y cómo se conectan. Es una vista estática: no describe el orden temporal de una compra o un préstamo.

Sí muestra: Cliente — realiza — Pedido.
No muestra: qué mensaje ocurre primero.

🧭 Tres niveles de intención

Un modelo puede ser conceptual, de diseño o cercano al código. Para empezar, conviene representar el dominio sin llenar el dibujo de detalles técnicos.

  • 💡 Conceptual: ideas del negocio.
  • 🛠️ Diseño: responsabilidades y tipos.
  • 💻 Implementación: detalles del lenguaje.

Relaciones y cantidades.

Un sustantivo no siempre termina como clase: “nombre” suele ser atributo y “pantalla” podría ser solo un detalle de interfaz.

Multiplicidad: ¿cuántos participan? 🔢

1

Exactamente uno.

0..1

Ninguno o uno.

*

Cualquier cantidad.

1..*

Uno o muchos.

Ejemplo: un Usuario puede tener 0..* Préstamos; cada Préstamo corresponde a 1 Usuario.

Asociación ──

Vínculo estable: Usuario realiza Reserva.

Composición ◆──

La parte depende del todo: Pedido contiene LíneasPedido.

Generalización ──▷

Una clase especializa otra: Estudiante es Persona.

Visibilidad en una mirada 🔐

+ público
- privado
# protegido
~ paquete

PlantUML reconoce estos cuatro marcadores; en este nivel usarás principalmente +, - y #.

Caso completo: biblioteca 📚

  • Entidades: Libro, Usuario y Préstamo.
  • Préstamo conserva fechaInicio y fechaDevolución.
  • Usuario puede solicitarPrestamo().
  • Préstamo conecta quién recibió qué libro.
  • Un Libro participa en muchos préstamos históricos, pero cada préstamo registra un solo libro.

Errores frecuentes del modelador 🧯

❌ Convertir cada sustantivo en clase.
✅ Pregunta si tiene identidad y responsabilidades.
❌ Dibujar líneas sin multiplicidad.
✅ Expresa las reglas de cantidad.
❌ Usar verbos como nombres de clase.
✅ Los verbos suelen inspirar operaciones.
❌ Agregar toda la base de datos.
✅ Muestra solo lo útil para el propósito.
