Paradigmas y pensamiento orientado a objetos 🧠

Los paradigmas de programación representan diferentes formas de diseñar y desarrollar soluciones de software. Comprender sus características permite seleccionar el enfoque más adecuado para resolver problemas y facilita la aplicación del pensamiento orientado a objetos en el desarrollo de aplicaciones modernas.

✨ Un problema puede observarse desde varios ángulos. Aprende a elegir la lente adecuada. 🚀

Objetivos de aprendizaje 🎯

  • 🧠Comprender el concepto de paradigma de programación y su importancia en el desarrollo de software.
  • 🔎Identificar las características de los principales paradigmas de programación.
  • 🧩Aplicar el pensamiento orientado a objetos mediante la identificación de clases, objetos, atributos y métodos.
📘 Primero: aprende a cambiar de lente

Un problema, distintas formas de pensarlo

Un paradigma no es una receta obligatoria: es un conjunto de ideas que orienta cómo dividimos un problema, representamos información y expresamos una solución. La misma tarea puede resolverse con varios estilos, cada uno destacando algo diferente.

🪜

Imperativo

Expresa una secuencia de órdenes y cambios de estado. Se enfoca en cómo avanzar.

double total = 0;
for (double precio : precios) {
  total += precio;
}
🎯

Declarativo

Describe la condición o resultado buscado y delega el procedimiento.

productos.stream()
  .filter(p -> p.stock() == 0)
  .toList();
🔗

Funcional

Transforma datos mediante funciones componibles y reduce efectos externos.

precios.stream()
  .map(p -> p * 0.9)
  .reduce(0.0, Double::sum);
🧱

Orientado a objetos

Distribuye estado y responsabilidades entre entidades que colaboran.

carrito.agregar(item);
carrito.calcularTotal();

Los paradigmas se pueden combinar 🤝

Java permite combinar clases y objetos, pasos imperativos y operaciones declarativas con Streams y expresiones lambda. El estilo funcional puede expresarse declarativamente. Por eso, “paradigma” no significa “lenguaje exclusivo”.

Java con objetos

Clases + estado + métodos.

Java imperativo

Variables + condiciones + bucles.

Java funcional

Streams + lambdas + transformaciones.

La misma meta: productos con descuento 🛒

Declarativa¿Qué conjunto quiero?Pedir productos que cumplan una condición.
Funcional¿Qué transformaciones compongo?Filtrar, transformar y reducir.
POO¿Quién conoce y hace cada cosa?Producto calcula; Carrito coordina.

Pensar en objetos: cuatro preguntas 🔍

  1. 1. ¿Quiénes participan? Cliente, Pedido, Producto.
  2. 2. ¿Qué saben? nombre, estado, precio.
  3. 3. ¿Qué hacen? comprar, confirmar, calcular.
  4. 4. ¿Cómo colaboran? Cliente crea Pedido; Pedido contiene productos.

Responsabilidad antes que datos 🎒

Un objeto útil no es una bolsa pasiva de campos. Debe proteger reglas y realizar acciones coherentes con su propósito.

❌ La pantalla calcula el total y modifica el stock.
✅ Pedido calcula su total; Producto controla su stock.

🎯 Abstracción

Conserva lo relevante para el propósito del modelo.

🔐 Encapsulamiento

Protege el estado detrás de operaciones controladas.

🌳 Herencia

Especializa un tipo y reutiliza comportamiento coherente.

🎭 Polimorfismo

El mismo mensaje produce respuestas propias de cada tipo.

Polimorfismo en acción 🎮

interface Figura { double area(); }
class Circulo implements Figura {
  private final double radio;
  Circulo(double radio) { this.radio = radio; }
  public double area() { return Math.PI * radio * radio; }
}
class Rectangulo implements Figura {
  private final double ancho, alto;
  Rectangulo(double ancho, double alto) {
    this.ancho = ancho; this.alto = alto;
  }
  public double area() { return ancho * alto; }
}
class Ejemplo {
  public static void main(String[] args) {
    Figura[] figuras = {new Circulo(2), new Rectangulo(3, 4)};
    for (Figura figura : figuras) {
      System.out.println(figura.area());
    }
  }
}

Oracle explica que las subclases pueden compartir funcionalidad y definir comportamientos propios.

¿Cuándo ayuda cada lente? 🧰

  • 🪜 Automatización paso a paso: imperativo.
  • 🔎 Consultas y reglas: declarativo.
  • 🔄 Transformación de colecciones: funcional.
  • 🏢 Dominios con entidades y reglas: objetos.
  • 🤝 Sistemas reales: combinación consciente.

Errores de pensamiento 🧯

  • ❌ Elegir paradigma solo por moda.
  • ❌ Creer que POO es crear muchas clases.
  • ❌ Usar herencia solo para copiar código.
  • ❌ Exponer todo el estado de un objeto.
  • ✅ Elegir según el problema, claridad y cambio esperado.
