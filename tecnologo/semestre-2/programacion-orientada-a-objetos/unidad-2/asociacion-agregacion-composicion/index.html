Asociación, agregación y composición 🔗

En la programación orientada a objetos, las clases no funcionan de manera aislada, sino que establecen relaciones para representar situaciones del mundo real. La asociación, la agregación y la composición permiten definir cómo los objetos colaboran, se contienen o dependen unos de otros dentro de un sistema.

✨ Aprenderás a decidir si dos objetos solo se conocen, forman un equipo o comparten su ciclo de vida. ¡Vamos a conectar ideas! 🚀

Objetivos de aprendizaje 🎯

  • 🔍Identificar las características de la asociación, la agregación y la composición.
  • ⚖️Diferenciar las relaciones entre objetos según su propiedad, independencia y ciclo de vida.
  • 💎Representar relaciones entre clases utilizando la notación básica de UML.
  • 🛠️Aplicar asociación, agregación y composición en el modelado de problemas orientados a objetos.

1. Base conceptual: tres preguntas antes de dibujar

🤝

¿Solo colaboran?

Si ambos objetos conservan identidad y vida propias, piensa en asociación. Ejemplo: una persona usa una aplicación.

🧺

¿Uno agrupa al otro?

Si hay un todo y partes reutilizables que sobreviven por separado, piensa en agregación. Ejemplo: una playlist agrupa canciones.

🧩

¿La parte nace para ese todo?

Si la parte pertenece a un único todo y pierde sentido al desaparecer este, piensa en composición. Ejemplo: una encuesta y sus preguntas.

Multiplicidad: cuenta posibilidades 🔢

1 exactamente uno · 0..1 opcional · 0..* ninguno o muchos · 1..* uno o muchos. Se lee en cada extremo: “para un objeto de aquí, ¿cuántos puede haber allá?”.

Navegabilidad: quién conoce a quién ➡️

Una flecha expresa acceso en una dirección. Dos referencias facilitan recorrer ambos sentidos, pero también aumentan el acoplamiento y la sincronización necesaria.

Errores que engañan incluso a programadores 👀

  • • Que una clase guarde otra en una lista no demuestra agregación: manda la regla del dominio.
  • • Composición no significa “borrar memoria manualmente”; comunica pertenencia y ciclo de vida en el modelo.
  • • No uses rombos solo para decorar: si “todo-parte” no tiene sentido, una asociación suele bastar.
  • • La multiplicidad describe restricciones del negocio, no cuántos datos existen hoy.

El mismo concepto en código JavaScript

// Asociación: recibe un objeto que ya existe
class Curso { asignarDocente(docente) { this.docente = docente; } }

// Agregación: el equipo reúne jugadores reutilizables
class Equipo { constructor(jugadores = []) { this.jugadores = jugadores; } }

// Composición: el pedido crea y controla sus líneas
class Pedido {
  constructor() { this.lineas = []; }
  agregar(producto, cantidad) { this.lineas.push({ producto, cantidad }); }
}
