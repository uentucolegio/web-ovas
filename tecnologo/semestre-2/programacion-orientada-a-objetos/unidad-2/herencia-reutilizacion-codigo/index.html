Herencia y reutilización de código 🌳

La herencia es un mecanismo de la programación orientada a objetos que permite crear clases especializadas a partir de clases más generales. Facilita la reutilización de atributos y métodos, reduce la duplicación de código y permite construir soluciones organizadas y extensibles.

✨ Hoy diseñarás familias de clases sin caer en el “copiar y pegar”. ¡Activa tu modo arquitecto! 🚀

Objetivos de aprendizaje 🎯

  • 🧠Comprender los conceptos de herencia, generalización y especialización.
  • 🔎Identificar superclases y subclases dentro de una jerarquía de clases.
  • 🐍Aplicar herencia, redefinición de métodos y super() en programas orientados a objetos.
  • ⚖️Diferenciar cuándo utilizar herencia y cuándo utilizar composición.

super(): sigue el MRO

class Persona:
    def __init__(self, nombre):
        self.nombre = nombre
    def presentarse(self):
        return f"Soy {self.nombre}"

class Estudiante(Persona):
    def __init__(self, nombre, ficha):
        super().__init__(nombre)
        self.ficha = ficha
    def presentarse(self):
        return super().presentarse() + \
               f" y estudio en {self.ficha}"

Lo importante 👀

  • ✅ super() busca el siguiente método según el MRO; no significa simplemente “mi padre”.
  • ✅ El override conserva el propósito de presentarse() y especializa el resultado.
  • ✅ La inicialización común vive en un solo lugar.
  • ⚠️ Omitir super().__init__() puede dejar atributos base sin crear.

Clases abstractas: contrato ejecutable 📜

Una clase que hereda de ABC puede marcar operaciones con @abstractmethod. Una subclase concreta no se instancia hasta implementarlas. Incluso un método abstracto puede ofrecer una base reutilizable llamada con super().

Herencia múltiple: cruce con semáforo 🚦

Python linealiza la jerarquía con C3. Consulta Clase.__mro__ para ver el orden. Funciona mejor con comportamientos cooperativos y super() consistente; si el modelo se vuelve confuso, composición suele ser más clara.

Alarmas de diseño 🚨

  • • Cuadrado hereda de Rectángulo puede romper expectativas si el cliente cambia ancho y alto por separado.
  • • Heredar solo para obtener dos métodos crea una relación conceptual falsa.
  • • Sobrescribir un método para lanzar “no soportado” suele romper sustitución.
  • • Árboles profundos hacen que un cambio arriba viaje por muchas clases.
