Polimorfismo e interfaces básicas 🎭

El polimorfismo permite que diferentes objetos respondan a una misma operación de acuerdo con su propia implementación. Junto con las interfaces, facilita la creación de sistemas flexibles, desacoplados y extensibles, donde nuevas implementaciones pueden incorporarse sin modificar el funcionamiento principal de la aplicación.

✨ Un mismo mensaje, muchas respuestas: hoy diseñarás software preparado para crecer. 🚀

Protocol: contrato estructural

from typing import Protocol

class Notificador(Protocol):
    def enviar(self, mensaje: str) -> None: ...

class Correo:
    def enviar(self, mensaje: str) -> None:
        print(f"Email: {mensaje}")

def avisar(canal: Notificador) -> None:
    canal.enviar("Tu pedido salió")

avisar(Correo())  # No heredó de Notificador

ABC: contrato nominal

from abc import ABC, abstractmethod

class Figura(ABC):
    @abstractmethod
    def area(self) -> float: ...

class Cuadrado(Figura):
    def __init__(self, lado): self.lado = lado
    def area(self): return self.lado ** 2

def total(figuras):
    return sum(f.area() for f in figuras)

Strategy: polimorfismo con propósito 🧠

Un contexto recibe un algoritmo intercambiable: envío terrestre, aéreo o marítimo. El contexto delega calcular_costo() y no crece con una cadena interminable de if. Es composición + contrato + despacho dinámico.

Cuatro trampas frecuentes 🚨

  • • Usar isinstance y ramificar por cada clase anula el beneficio polimórfico.
  • • Una interfaz gigante obliga a implementar operaciones inútiles: sepárala por capacidades.
  • • Duck typing no significa “sin contrato”: tipos, pruebas y documentación vuelven visible la expectativa.
  • • @runtime_checkable comprueba que existan miembros, no que sus firmas o tipos sean correctos.
