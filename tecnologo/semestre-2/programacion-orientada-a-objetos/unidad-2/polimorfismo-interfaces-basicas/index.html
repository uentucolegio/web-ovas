Polimorfismo e interfaces básicas 🎭

El polimorfismo permite que diferentes objetos respondan a una misma operación de acuerdo con su propia implementación. Junto con las interfaces, facilita la creación de sistemas flexibles, desacoplados y extensibles, donde nuevas implementaciones pueden incorporarse sin modificar el funcionamiento principal de la aplicación.

✨ Un mismo mensaje, muchas respuestas: hoy diseñarás software preparado para crecer. 🚀

Interfaz: contrato nominal

interface Notificador {
    void enviar(String mensaje);
}

class Correo implements Notificador {
    @Override
    public void enviar(String mensaje) {
        System.out.println("Email: " + mensaje);
    }
}

class Avisos {
    static void avisar(Notificador canal) {
        canal.enviar("Tu pedido salió");
    }
    public static void main(String[] args) {
        avisar(new Correo());
    }
}

Clase abstracta: contrato y estado

abstract class Figura {
    public abstract double area();
}

class Cuadrado extends Figura {
    private final double lado;
    Cuadrado(double lado) { this.lado = lado; }
    @Override
    public double area() { return lado * lado; }
}

class Geometria {
    static double total(Figura[] figuras) {
        double suma = 0;
        for (Figura figura : figuras) {
            suma += figura.area();
        }
        return suma;
    }
}

Inyección: cambia la pieza desde afuera 🔌

// Utiliza la interfaz Notificador del ejemplo anterior.
class Alerta {
    private final Notificador canal;
    Alerta(Notificador canal) {
        this.canal = canal;
    }
    void confirmar() {
        canal.enviar("Listo");
    }
}

class CanalFalso implements Notificador {
    String ultimoMensaje;
    @Override
    public void enviar(String mensaje) {
        ultimoMensaje = mensaje;
    }
}
// Producción: new Alerta(new Correo()).confirmar();
// Prueba: new Alerta(new CanalFalso()).confirmar();

La lógica depende de la capacidad enviar, no de una marca concreta.

Strategy: polimorfismo con propósito 🧠

Un contexto recibe un algoritmo intercambiable: envío terrestre, aéreo o marítimo. El contexto delega calcularCosto() y no crece con una cadena interminable de if. Es composición + contrato + despacho dinámico.

Cuatro trampas frecuentes 🚨

  • • Usar instanceof y ramificar por cada clase anula el beneficio polimórfico.
  • • Una interfaz gigante obliga a implementar operaciones inútiles: sepárala por capacidades.
  • • Una clase debe declarar o heredar la interfaz que implementa; coincidir en los nombres de métodos no basta.
  • • @Override verifica la firma; las pruebas verifican que el comportamiento respete el contrato.
