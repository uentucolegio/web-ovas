Sobrecarga y sobreescritura de métodos 🔀

La sobrecarga y la sobreescritura permiten crear operaciones flexibles y comportamientos especializados en programación orientada a objetos. Aunque ambas pueden utilizar un mismo nombre de método, la sobrecarga varía la forma de invocarlo, mientras que la sobreescritura modifica su comportamiento en una subclase.

✨ Hoy controlarás dos poderes con nombres parecidos, pero decisiones muy distintas. ¡Que comience el duelo de métodos! ⚔️

Objetivos de aprendizaje 🎯

  • ⚖️Diferenciar la sobrecarga y la sobreescritura de métodos.
  • ⏱️Comprender el despacho estático y dinámico en programación orientada a objetos.
  • 🐍Aplicar técnicas de Python para crear métodos flexibles mediante parámetros opcionales y despacho por tipo.
  • 🛡️Implementar sobreescritura respetando el contrato de la superclase.
  • △Representar sobrecarga y sobreescritura mediante UML.

1. Base conceptual: ¿qué cambia?

📞

Sobrecarga: cambia la llamada

Un mismo propósito admite distintas listas o tipos de argumentos. En Java el compilador elige una firma. En Python se modela con una implementación flexible o despacho registrado.

sumar(2, 3) · sumar(2, 3, 4)

🎭

Sobreescritura: cambia el objeto

La subclase sustituye una operación heredada con otra implementación compatible. El tipo real del receptor decide durante la ejecución.

Perro().hablar() · Gato().hablar()

Parámetro opcional

def saludar(nombre, emoji="👋"):
    return f"Hola {nombre} {emoji}"

Ideal cuando la intención es una y hay una variación pequeña.

*args con validación

def sumar(*valores):
    if not valores:
        raise ValueError("Faltan datos")
    return sum(valores)

Flexible, pero el contrato debe decir cuántos y cuáles datos acepta.

typing.overload

@overload
def leer(id: int) -> Registro: ...
@overload
def leer(id: None) -> list[Registro]: ...
def leer(id=None):
    # única implementación real
    ...

Las variantes ayudan al verificador; una definición final ejecuta el trabajo.

singledispatchmethod: mira un tipo

class Formateador:
 @singledispatchmethod
 def mostrar(self, dato):
    return str(dato)

 @mostrar.register
 def _(self, dato: list):
    return ", ".join(dato)

Despacha por el primer argumento que no sea self ni cls. Si no hay coincidencia exacta, busca una opción más general usando el MRO.

Sobreescritura + super()

class Notificacion:
 def enviar(self, texto):
    return f"Registro: {texto}"

class Email(Notificacion):
 def enviar(self, texto):
    base = super().enviar(texto)
    return base + " | Email enviado"

super() sigue el MRO y permite extender la regla común sin duplicarla.

Operadores: diseña significado, no sorpresa ➕

__add__, __eq__ y __len__ conectan objetos con +, == y len(). Un Vector + Vector es comprensible; Usuario + Factura probablemente no.

Detalle útil: si __eq__ cambia y no defines __hash__, las instancias pasan a ser no hashables por seguridad.

Radar de errores 🚨

  • • En Python, dos def calcular(...) en la misma clase no crean sobrecarga: la última reemplaza la anterior.
  • • typing.overload no elige implementaciones en ejecución; documenta variantes para el análisis estático.
  • • Agregar un parámetro obligatorio al override rompe llamadas válidas de la clase base.
  • • *args sin límites ni validación oculta el contrato en vez de hacerlo flexible.
