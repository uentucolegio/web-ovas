Pruebas unitarias introductorias 🚀

Una calculadora de tarifas funciona para tres unidades. ¿Basta para confiar en ella? Podría fallar con cero, aceptar cantidades negativas o depender de un estado que dejó otra operación. Una prueba es un experimento con condiciones, acción y resultado esperado definidos.

Las pruebas unitarias se concentran en comportamientos pequeños y dan respuesta rápida durante el desarrollo. No reemplazan las comprobaciones de integración ni la revisión de requisitos. Ejecutar muchas líneas sin verificar resultados relevantes puede dejar errores importantes sin detectar.

La base es Java 17. Se presenta primero un programa autónomo que permite reconocer una comprobación automática y luego una suite completa con JUnit Jupiter 5.11.4. Se fija esa versión para reproducir el ejercicio, sin presentarla como la más reciente.

Contrato: cantidad entera 0..10 y precio 2500 centavos por unidad. Escribe primero 3 → 7500. No calcules el esperado copiando el algoritmo bajo prueba: podrías duplicar su defecto.

🎮 Reto de 10 puntos: ¿Cuál es un oráculo independiente?

Crea los datos de cada caso, ejecuta una operación y verifica sus efectos. Varias aserciones pueden cubrir un mismo comportamiento. Compartir una lista mutable entre pruebas crea dependencias de orden.

🎮 Reto de 10 puntos: ¿Cómo haces independiente una prueba de saldo?

Prueba -1, 0, 1, 9, 10 y 11; agrega 3 como caso ordinario. Los vecinos detectan errores de comparación. Pruebas solo de rechazo aceptarían una función defectuosa que rechaza todo.

🎮 Reto de 10 puntos: ¿Qué caso detecta cambiar > 10 por >= 10?

@Test identifica el experimento. assertEquals compara enteros y assertThrows comprueba un rechazo compatible con el tipo solicitado. Comprueba también el estado si hubo una operación fallida. Las aserciones JUnit no dependen de -ea.

🎮 Reto de 10 puntos: ¿Qué verifica assertThrows por sí solo?

Un fake en memoria ayuda a aislar reglas; no demuestra que una consulta real funcione. Una suite escrita todavía debe descubrirse y ejecutarse. Cobertura indica recorrido, no calidad del esperado.

public class PruebasTarifa {
    public static int calcular(int cantidad) {
        if (cantidad < 0 || cantidad > 10) {
            throw new IllegalArgumentException("Cantidad fuera de 0..10");
        }
        return cantidad * 2500;
    }
    static void igual(int esperado, int actual) {
        if (esperado != actual) {
            throw new AssertionError("Esperado " + esperado + ", actual " + actual);
        }
    }
    static void rechaza(int cantidad) {
        try {
            calcular(cantidad);
        } catch (IllegalArgumentException e) {
            return;
        }
        throw new AssertionError("Debio rechazar " + cantidad);
    }
    public static void main(String[] args) {
        igual(0, calcular(0));
        igual(7500, calcular(3));
        igual(25000, calcular(10));
        rechaza(-1);
        rechaza(11);
        System.out.println("5 comprobaciones correctas");
    }
}

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

public class TarifaTest {
    @Test
    void aceptaCero() {
        assertEquals(0, PruebasTarifa.calcular(0));
    }
    @Test
    void calculaTresUnidades() {
        assertEquals(7500, PruebasTarifa.calcular(3));
    }
    @Test
    void aceptaLimiteSuperior() {
        assertEquals(25000, PruebasTarifa.calcular(10));
    }
    @Test
    void rechazaNegativo() {
        assertThrows(IllegalArgumentException.class,
        () -> PruebasTarifa.calcular(-1));
    }
    @Test
    void rechazaOnce() {
        assertThrows(IllegalArgumentException.class,
        () -> PruebasTarifa.calcular(11));
    }
}
